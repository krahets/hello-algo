# 6.4 &nbsp; まとめ

### 1. &nbsp; 要点の振り返り

- ハッシュ表では `key` を入力すると、対応する `value` を $O(1)$ 時間で取得でき、非常に効率的です。
- ハッシュ表の代表的な操作には、検索、ペアの追加と削除、表の走査などがあります。
- ハッシュ関数で `key` を配列のインデックスに対応づけ、そのバケットにアクセスして `value` を取り出します。
- 異なる 2 つの `key` から同じインデックスが得られ、検索結果が誤る場合があります。この現象をハッシュ衝突と呼びます。
- ハッシュ表の容量が大きいほど衝突の確率は低くなるため、表の拡張で衝突を軽減できます。ただし、配列の拡張と同じく、表の拡張には大きなコストがかかります。
- 負荷率は、表内の要素数をバケット数で割った値です。衝突の起きやすさを表し、表を拡張する条件としてよく使われます。
- チェイン法では、単一の要素を置いていたところに連結リストを置き、衝突した要素をすべて同じリストに格納します。リストが長くなると検索効率が下がりますが、リストをさらに赤黒木に変換すれば改善できます。
- オープンアドレス法は、複数の位置を順に調べて衝突に対処します。線形探索法は一定幅で進みますが、要素を直接削除できず、クラスタリングも起きやすいという弱点があります。複数のハッシュ関数を使う方法では、線形探索法よりクラスタリングが起きにくい一方、関数の計算量が増えます。
- ハッシュ表の実装は言語によって異なります。例えば Java の `HashMap` はチェイン法を使い、Python の `dict` はオープンアドレス法を使います。
- ハッシュ表に使うアルゴリズムには、同じ入力から同じ出力が得られ、計算が速く、値が均一に分布することが求められます。暗号分野では、さらに衝突耐性と雪崩効果も必要です。
- 通常、ハッシュアルゴリズムでは法に大きな素数を使い、ハッシュ値の分布をできるだけ均一にして衝突を減らします。
- 代表的なハッシュアルゴリズムには MD5、SHA-1、SHA-2、SHA-3 などがあります。MD5 はファイルの完全性の確認に、SHA-2 はセキュリティ用途やプロトコルによく使われます。
- プログラミング言語には通常、データ型ごとのハッシュアルゴリズムが組み込まれており、バケットのインデックスの計算に使えます。一般には不変なオブジェクトだけがハッシュ可能です。

### 2. &nbsp; Q & A

**Q**：ハッシュ表の時間計算量が $O(n)$ になるのはどのような場合ですか。

衝突が多いと、ハッシュ表の時間計算量は $O(n)$ に悪化します。ハッシュ関数の設計がよく、容量が適切で、衝突が均等に分散していれば、時間計算量は $O(1)$ です。言語に組み込まれたハッシュ表を使うときは、通常 $O(1)$ と考えます。

**Q**：ハッシュ関数を $f(x) = x$ にすれば衝突しないのに、なぜそうしないのですか。

ハッシュ関数が $f(x) = x$ なら、各要素に固有のバケットのインデックスが対応するので、配列と同じになります。しかし、入力の範囲は通常、出力の範囲（配列の長さ）よりはるかに広いため、ハッシュ関数の最後に配列の長さで割った余りを取るのが一般的です。ハッシュ表の目的は、広い範囲の状態をより小さな範囲に対応づけ、$O(1)$ で検索できるようにすることです。

**Q**：ハッシュ表の内部には配列や連結リスト、二分木を使うのに、どうしてそれらよりも効率がよくなるのですか。

まず、時間効率が上がる一方で、空間効率は下がります。ハッシュ表には、使っていないメモリ領域がかなりあります。

次に、時間効率がよくなるのは特定の用途に限られます。同じ時間計算量で配列や連結リストを使って実現できる機能なら、そちらのほうが通常は高速です。ハッシュ表ではハッシュ関数を計算するコストがかかり、計算時間の定数係数が大きくなるからです。

最後に、ハッシュ表の時間計算量は悪化することもあります。例えばチェイン法では、連結リストや赤黒木の中で検索を行うため、表の検索には依然として $O(n)$ 時間まで悪化する可能性があります。

**Q**：複数のハッシュ関数を使う方法でも、要素を直接削除することはできませんか。削除済みの印を付けた場所は再利用できますか。

この方法もオープンアドレス法の一種です。いずれのオープンアドレス法でも、要素を直接削除することはできず、印を付けて削除します。削除済みの位置は再利用できます。新しい要素を挿入するとき、ハッシュ関数で見つけた位置が削除済みなら、そこに新しい要素を格納できます。こうすると探索順序を保ちながら、表の領域を有効に使えます。

**Q**：線形探索法では、なぜ要素を探すときにもハッシュ衝突が起きるのですか。

検索時にハッシュ関数でバケットを特定し、中のペアを調べて `key` が一致しなければ、衝突しているということです。そこで線形探索法では、決められたステップ幅で順に先を調べ、正しいペアが見つかるか、見つからないとわかるまで探索を続けます。

**Q**：なぜハッシュ表を拡張すると衝突が減るのですか。

ハッシュ関数では通常、最後に配列の長さ $n$ で割った余りを取り、出力をインデックスの範囲に収めます。拡張すると配列の長さ $n$ が変わるので、`key` に対応するインデックスも変わることがあります。それまで同じバケットに入っていた複数の `key` が別々のバケットに割り当てられるようになり、衝突が減ります。

**Q**：効率よく読み書きしたいなら、配列を直接使えばよいのではありませんか。

データの `key` が狭い範囲の連続した整数なら、配列を直接使うのが簡単で効率的です。一方、`key` が文字列などのほかの型なら、ハッシュ関数で `key` を配列のインデックスに変換し、バケットの配列に要素を格納する必要があります。これがハッシュ表です。
