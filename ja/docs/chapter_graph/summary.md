# 9.4 &nbsp; まとめ

### 1. &nbsp; 要点の振り返り

- グラフは頂点と辺からなり、頂点集合と辺集合の組で表せます。
- ネットワーク状の関係（グラフ）は、線形の関係（連結リスト）や分割統治の関係（木）より自由度が高く、その分だけ複雑です。
- 有向グラフの辺には向きがあります。連結グラフではどの頂点にも到達でき、重み付きグラフでは各辺に重みを表す変数があります。
- 隣接行列はグラフを行列で表します。各行と各列が頂点に、各要素が辺に対応し、2 頂点間に辺があれば $1$、なければ $0$ を格納します。辺の追加、削除、検索、更新は効率的ですが、多くの記憶領域を使います。
- 隣接リストはグラフを複数の連結リストで表します。$i$ 番目のリストは頂点 $i$ に対応し、その頂点の隣接頂点をすべて格納します。隣接行列よりも記憶領域を節約できますが、辺を探すにはリストを走査するため、時間効率は下がります。
- 隣接リスト内の連結リストが長くなりすぎるときは、赤黒木やハッシュテーブルに置き換えて検索効率を高められます。
- アルゴリズムの考え方として、隣接行列は空間を使って時間を節約し、隣接リストは時間をかけて空間を節約します。
- グラフは、ソーシャルネットワークや地下鉄の路線など、実世界のさまざまなシステムのモデル化に使えます。
- 木はグラフの特殊な場合で、木の探索もグラフの探索の特殊な場合です。
- グラフの幅優先探索は、近い頂点から遠い頂点へと探索範囲を層ごとに広げる方法で、通常はキューを使って実装します。
- グラフの深さ優先探索は、まず行き止まりまで進み、それ以上進めなくなってから戻る方法で、多くの場合は再帰で実装します。

### 2. &nbsp; Q & A

**Q**：経路は頂点の列として定義しますか、それとも辺の列として定義しますか。

ウィキペディアの定義は言語版によって異なります。英語版では「経路は辺の列」、中国語版では「経路は頂点の列」とされています。英語版の原文は次のとおりです。In graph theory, a path in a graph is a finite or infinite sequence of edges which joins a sequence of vertices.

本書では経路を頂点の列ではなく辺の列として扱います。2 頂点間を結ぶ辺が複数ある場合、それぞれの辺に別々の経路が対応するからです。

**Q**：非連結グラフには探索で到達できない頂点がありますか。

非連結グラフでは、ある頂点から出発しても到達できない頂点が少なくとも 1 つあります。全頂点を訪問するには、始点を複数設けてすべての連結成分を探索します。

**Q**：隣接リストで「この頂点に接続するすべての頂点」を並べる順序に決まりはありますか。

順序は任意です。ただし実際の用途では、頂点を追加した順や頂点の値の大小など、決まった規則で並べておくことがあります。そうすると、ある基準で最大や最小になる頂点を素早く探せます。
