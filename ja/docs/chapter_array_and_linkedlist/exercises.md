# 練習問題

## 理解を確かめる問題

### 配列と連結リストで要素にアクセスする方法

配列と単方向連結リストのどちらにも `[A, B, C, D, E]` が順に格納されています。4 番目の要素 `D` を読み出す場合を考えます。

<!-- numbered-subquestions -->

1. 配列では、どのインデックスを直接指定すればよいでしょうか。
2. 単方向連結リストでは、先頭ノード `A` から `next` をたどると、どのノードをどんな順に通るでしょうか。
3. 読み出す位置が末尾に近づくにつれ、それぞれの構造で必要な手数はどう変わりますか。位置を指定して繰り返し読み出すにはどちらが適していますか。理由も説明してください。

??? success "解答例"

    1. インデックスが 0 から始まるなら、4 番目の要素のインデックスは 3 なので、配列では `arr[3]` を直接読み出せます。

    2. 単方向連結リストでは先頭から始める必要があります。経路は `A → B → C → D` で、`next` を 3 回たどります。

    3. 配列では先頭アドレスとインデックスから要素の位置を直接求められるので、位置を指定してアクセスする時間計算量は $O(1)$ です。
        単方向連結リストの $k$ 番目のノードにアクセスするには、先頭ノードから `next` を $k-1$ 回たどる必要があり、
        最悪の場合は $O(n)$ の時間がかかります。

        ここで比較しているのは位置を指定した読み出しです。あらゆる操作で連結リストのほうが遅いという意味ではありません。

### 配列と連結リストに要素を挿入する方法

配列と単方向連結リストのどちらにも `A、B、C、D` が入っています。`B` の直後に `X` を挿入する場合を考えます。

- 配列の容量は 5 で、現在の状態は `[A, B, C, D, _]` です。
- 連結リストは `A → B → C → D` で、ノード `B` への参照はすでに得られています。

<!-- numbered-subquestions -->

1. 配列ではどの要素を移動する必要がありますか。挿入後の配列を書いてください。
2. 連結リストでは `X.next` と `B.next` をどの順に書き換えればよいですか。挿入後のリストを書いてください。
3. 挿入の効率を比較するとき、「ノード B への参照はすでに得られている」と明記するのはなぜでしょうか。

??? success "解答例"

    1. 配列ではまず `D` を右に 1 つずらし、次に `C` を右に 1 つずらします。最後に `X` をインデックス 2 に入れると、
        結果は `[A, B, X, C, D]` になります。

    2. `B.next` はもともと `C` を指しています。まず `X.next = B.next` として、`X` が `C` を指すようにします。
        次に `B.next = X` とします。結果は `A → B → X → C → D` です。
        先に `B.next` を上書きすると、元のリンクを保存していない場合は `C` を見失うおそれがあります。

    3. `B` の位置がわかっていれば、連結リストへの挿入ではリンクを 2 つ書き換えるだけなので、$O(1)$ 時間で完了します。
        先頭から `B` を探す必要があれば、探索自体に $O(n)$ の時間がかかることがあります。

### リストの容量が増える仕組み

配列で実装したリストの内容が `[A, B, C]`、長さが `size = 3`、容量が `capacity = 4` であるとします。
容量が足りなくなったら、元の 2 倍の容量を持つ新しい配列を使うものとします。

<!-- numbered-subquestions -->

1. `D` を末尾に追加した後、リストの長さと容量はいくつになりますか。容量を増やす必要はありますか。
2. 続いて `E` を末尾に追加すると、容量はいくつになりますか。元の要素をいくつコピーする必要がありますか。
3. 内部の配列の長さは変えられないのに、リストの容量を増やせるように見えるのはなぜでしょうか。

??? success "解答例"

    1. `D` は最後の空きに入ります。この時点で内容は `[A, B, C, D]` となり、
        `size = 4`、`capacity = 4` です。容量を増やす必要はありません。

    2. さらに `E` を末尾に追加する際には空きがないので、容量 8 の新しい配列を作り、
        元の 4 要素 `A、B、C、D` をコピーしてから `E` を追加します。
        この時点で `size = 5`、`capacity = 8` です。

    3. 元の配列自体が長くなったわけではありません。リストはより大きな配列を作って元の要素をコピーし、
        内部の格納先を新しい配列に切り替えます。こうして利用者から見た容量が増えます。

## プログラミング問題

### 配列で表した大きな整数に 1 を足す

配列 `digits` には、非負整数の各桁の数字が左から順に入っています。たとえば、`[3, 0, 8]` は 308 を表します。
数値 0 は `[0]` で表します。それ以外の入力では、先頭の桁は 0 以外です。

十進数の足し算の筆算を再現して、この整数に 1 を足し、結果を同じ形式の配列で返してください。
`digits` は直接書き換えてかまいません。最上位の桁から繰り上がる場合は、より長い配列を返してかまいません。

??? tip "解き方のヒント"

    1. 足し算の筆算と同じように、配列の末尾の桁から始めます。
    2. 今見ている桁が 9 より小さければ、1 を足してすぐに結果を返せます。
    3. 今見ている桁が 9 なら 0 に書き換えます。すべての桁が 9 なら、先頭に 1 を追加します。

[LeetCode](https://leetcode.com/problems/plus-one/){ .rounded-button .exercise-button target="_blank" rel="noopener noreferrer" }

### 単方向連結リストを逆順にする

単方向連結リストの先頭ノード `head` が与えられます。各ノードは、値と次のノードを指す `next` を持ちます。

反復処理ですべてのノード間のリンクの向きを反転し、新しい先頭ノードを返してください。
新たなリストノードは作成しないでください。

??? tip "解き方のヒント"

    1. まず、3 個のノードがつながった図と、prev、cur の 2 本のポインタを紙に描いてみましょう。
    2. cur.next を書き換える前に、元の次ノードを必ず nxt に保存します。
    3. cur.next の向きを反転したら、prev = cur、続いて cur = nxt として、元のリストの次のノードを処理します。

[LeetCode](https://leetcode.com/problems/reverse-linked-list/){ .rounded-button .exercise-button target="_blank" rel="noopener noreferrer" }
