# 1.2 &nbsp; アルゴリズムとは

## 1.2.1 &nbsp; アルゴリズムの定義

<u>アルゴリズム（algorithm）</u>は、有限の時間内に特定の問題を解くための命令や操作手順の集まりで、次の特徴を持ちます。

- 問題が明確であり、入力と出力がはっきり定義されています。
- 実行可能であり、有限の手順、時間、メモリ領域で完了できます。
- 各手順の意味が明確で、同じ入力と実行条件なら、出力は常に同じになります。

## 1.2.2 &nbsp; データ構造の定義

<u>データ構造（data structure）</u>は、データを組織化して格納する方法です。データの内容、データ間の関係、操作方法を含み、次の設計目標を持ちます。

- 使用領域をできるだけ減らし、コンピュータのメモリを節約します。
- アクセス、追加、削除、更新などの操作をできるだけ速くします。
- データと論理的な情報を簡潔に表現し、アルゴリズムが効率よく動作できるようにします。

**データ構造の設計は、さまざまなトレードオフを伴う過程です**。ある面を改善するには、別の面で妥協が必要になることがよくあります。二つ例を挙げます。

- 連結リストは配列より追加や削除が容易ですが、データへのアクセス速度を犠牲にしています。
- グラフは連結リストより豊かな論理情報を表せますが、より多くのメモリを使います。

## 1.2.3 &nbsp; データ構造とアルゴリズムの関係

図 1-4 のように、データ構造とアルゴリズムは強く関連し、密接に結び付いています。具体的には次の三点に表れます。

- データ構造はアルゴリズムの土台です。構造化して格納したデータと、それを操作する方法を提供します。
- アルゴリズムはデータ構造に生命を吹き込みます。データ構造自体は情報を格納するだけですが、アルゴリズムと組み合わせると特定の問題を解けます。
- 通常、一つのアルゴリズムは異なるデータ構造で実装できますが、実行効率には大きな差が生じる場合があります。適切なデータ構造の選択が鍵となります。

データ構造とアルゴリズムはプログラミング言語に依存しません。だからこそ、本書では複数の言語による実装を提供できています。

!!! tip "慣用的な略称"

    実際の議論では、「データ構造とアルゴリズム」を「アルゴリズム」と略すことがよくあります。例えば、よく知られる LeetCode のアルゴリズム問題も、実際にはデータ構造とアルゴリズムの両方の知識を問うものです。
