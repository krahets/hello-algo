# 2.1 &nbsp; アルゴリズムの効率の評価

アルゴリズムの設計には、順に目指す 2 つの目標があります。

1. **問題の解き方を見つける**：指定された範囲の入力に対して、確実に正しい解を求められることが必要です。
2. **最適な解き方を探す**：同じ問題にも複数の解き方があり得ます。その中でできる限り効率のよいアルゴリズムを探します。

つまり、問題を解けることを前提にすると、アルゴリズムの良し悪しを測る主な指標は効率です。効率には次の 2 つの側面があります。

- **時間効率**：アルゴリズムの実行にかかる時間です。
- **空間効率**：アルゴリズムが使うメモリ領域の大きさです。

一言でいえば、**目指すのは、速く動き、メモリを節約できるデータ構造とアルゴリズムを設計することです**。そのためには効率を適切に評価する必要があります。そうして初めて、さまざまなアルゴリズムを比較し、その結果を設計や最適化に生かせます。

効率の評価方法は、大きく実測と理論的な見積もりに分けられます。

## 2.1.1 &nbsp; 実測

同じ問題を解けるアルゴリズム `A` と `B` の効率を比べたいとします。最も直接的な方法は、コンピュータで両方を実行し、実行時間とメモリ使用量を測定して記録することです。実際の動作を反映できる一方で、大きな制約もあります。

一つは、**測定環境の影響を取り除きにくいことです**。アルゴリズムの性能はハードウェア構成に左右されます。例えば並列性の高いアルゴリズムはマルチコア CPU に向き、メモリへのアクセスが多いアルゴリズムは高性能なメモリでよりよく動作します。つまり、マシンが違えば測定結果も変わり得ます。さまざまなマシンで測定して平均的な効率を求める必要があり、これは現実的ではありません。

もう一つは、**十分な測定を行うには非常に多くの資源が必要なことです**。入力データの量が変わると、アルゴリズムの効率も変わります。例えば入力が小さいときは `A` のほうが `B` より短時間で動作しても、入力が大きくなると結果が逆転するかもしれません。説得力のある結論を得るには、さまざまなサイズの入力で測定する必要があり、多くの計算資源を消費します。

## 2.1.2 &nbsp; 理論的な見積もり

実測にはこうした制約があるため、実行せずに計算だけで効率を評価する方法を考えます。この見積もり方を<u>漸近計算量解析（asymptotic complexity analysis）</u>、略して<u>計算量解析</u>と呼びます。

計算量解析を使うと、アルゴリズムの実行に必要な時間やメモリと、入力データのサイズとの関係がわかります。**入力サイズが大きくなるにつれて、実行に必要な時間とメモリがどのように増えるかを表します**。少し抽象的なので、3 つのポイントに分けて考えましょう。

- 「時間とメモリ」は、それぞれ<u>時間計算量（time complexity）</u>と<u>空間計算量（space complexity）</u>に対応します。
- 「入力サイズが大きくなるにつれて」とは、計算量がアルゴリズムの実行効率と入力サイズの関係を表すということです。
- 「時間とメモリがどのように増えるか」とは、実行時間やメモリ使用量の具体的な値よりも、それぞれの増え方の速さに着目するということです。

**計算量解析は実測の弱点を補います**。具体的には、次の利点があります。

- コードを実行する必要がないので、エネルギーを節約でき、環境への負担も小さくなります。
- 測定環境に左右されず、分析結果はどの実行環境にも適用できます。
- さまざまなデータ量での効率、とりわけ大量のデータを扱うときの性能がわかります。

!!! tip "ヒント"

    まだ計算量の概念をつかめなくても心配はいりません。この後の節で詳しく説明します。

計算量解析は、アルゴリズムの効率を評価する「ものさし」です。実行に必要な時間とメモリを見積もり、異なるアルゴリズムの効率を比較できます。

計算量は数学的な概念なので、初学者には抽象的で、やや難しく感じられるかもしれません。その点では、最初に学ぶ題材としては少し取り組みにくいでしょう。しかし、データ構造やアルゴリズムの特徴を説明するには、実行速度とメモリの使い方を分析する必要があります。

そこで、データ構造とアルゴリズムの学習を深める前に、**まず計算量解析の基本を押さえ、簡単なアルゴリズムの計算量を分析できるようにしておきましょう**。
