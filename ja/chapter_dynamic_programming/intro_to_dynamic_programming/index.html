14.1   動的計画法入門¶

動的計画法（dynamic programming）は、アルゴリズム設計の重要な手法です。問題をより小さな部分問題に分解し、その解を保存して重複計算を避けることで、計算時間を大幅に短縮します。

この節では代表的な例題を取り上げます。まずバックトラックによる全探索で解き、部分問題の重複を確かめてから、より効率のよい動的計画法を段階的に導きます。

階段の登り方

\(n\) 段の階段を、1 歩で \(1\) 段または \(2\) 段登れます。最上段までの登り方は何通りありますか。

図 14-1 のように、\(3\) 段の階段では最上段までの登り方は \(3\) 通りあります。

図 14-1   3 段目までの登り方の数

図解 14-1：3 段目までの 3 通りの登り方

階段に描いた 3 本の経路が、3 段目までの異なる登り方を示します。

地面の出発点を 0 とし、1 歩で 1 段か 2 段登ります。目標はちょうど 3 段目に着くことです。

階段には左から右に 0～6 の番号があり、目標の 3 段目の踏み面は緑です。同じ階段の上に 3 組の弧があり、それぞれが下の段の並びと対応します。下には「3 段目までの登り方は 3 通り」とあります。

青緑の実線 0→1→2→3 は 1 段ずつ 3 回登ります。青の点線 0→2→3 は 2 段登って 2 段目に着き、次に 1 段登って 3 段目に着きます。オレンジの破線 0→1→3 は 1 段登って 1 段目に着き、次に 2 段登って 3 段目に着きます。2 段、1 段の順と 1 段、2 段の順では通る段が違うため、別々に数えます。

目標は登り方を数えることなので、バックトラックですべての可能性を列挙できます。地面から出発し、毎回 \(1\) 段か \(2\) 段かを選ぶと考えましょう。最上段に着くたびに通り数に \(1\) を加え、最上段を越えたらその分岐を打ち切ります。コードは次のとおりです。

climbing_stairs_backtrack.py
def backtrack(choices: list[int], state: int, n: int, res: list[int]) -> int:
    """バックトラック"""
    # n 段目に着いたら、登り方の数を 1 増やす
    if state == n:
        res[0] += 1
    # すべての選択肢を調べる
    for choice in choices:
        # 枝刈り：n 段目を越えないようにする
        if state + choice > n:
            continue
        # 選択肢を試し、状態を更新する
        backtrack(choices, state + choice, n, res)
        # 選択を取り消す

14.1.1   方法 1：全探索¶

バックトラックでは通常、問題を明示的に分解しません。問題を解くことを一連の選択と捉え、選択肢を試しながら枝刈りし、可能な解をすべて探索します。

今度は問題を分解する観点から考えましょう。\(i\) 段目までの登り方を \(dp[i]\) 通りとすると、元の問題は \(dp[i]\) であり、次の部分問題が含まれます。

\[ dp[i-1], dp[i-2], \dots, dp[2], dp[1] \]

1 歩で登れるのは \(1\) 段か \(2\) 段なので、\(i\) 段目に着く直前にいたのは \(i - 1\) 段目か \(i - 2\) 段目です。つまり、\(i\) 段目に進めるのは \(i -1\) 段目か \(i - 2\) 段目からだけです。

ここから大切な関係がわかります。\(i - 1\) 段目までの登り方の数と \(i - 2\) 段目までの登り方の数の和は、\(i\) 段目までの登り方の数に等しくなります。式で表すと次のようになります。

\[ dp[i] = dp[i-1] + dp[i-2] \]

つまり階段の問題では、部分問題の間に漸化式が成り立ち、部分問題の解から元の問題の解を構成できます。図 14-2 にこの関係を示します。

図 14-2   登り方の数の漸化式

図解 14-2：5 段目までの通り数は 3 段目と 4 段目までの通り数の和

5 段目への最後の 1 歩は 3 段目か 4 段目からしか来られないので、登り方は 3+5=8 通りです。

1 歩で 1 段か 2 段登れ、n 段目までの登り方の数を dp[n] とします。初期状態は dp[1]=1、dp[2]=2 です。

3、4、5 段目は順に緑、青緑、青で強調されています。3 本の緑の破線が 3 段目（dp[3]=3）に、5 本の青緑の実線が 4 段目（dp[4]=5）に集まります。そこから 2 段またぐ緑の破線と 1 段またぐ青緑の実線が 1 本ずつ 5 段目に合流します。上には dp[5]=dp[3]+dp[4]=8、下には 1～6 段目と各段までの通り数が並びます。

5 段目には 3 段目から 2 段登るか、4 段目から 1 段登るかのどちらかで着きます。3 段目までの 3 通りのそれぞれに 2 段の 1 歩を足すと 3 通り、4 段目までの 5 通りのそれぞれに 1 段の 1 歩を足すとさらに 5 通りです。最後の 1 歩の出発点で分けたため重複も漏れもなく、dp[5]=dp[3]+dp[4]=3+5=8 です。一般に i 段目（i≥3）では dp[i]=dp[i-1]+dp[i-2] が成り立ちます。

漸化式を使うと全探索で解けます。\(dp[n]\) から出発し、大きな問題をより小さい 2 つの問題の解の和に再帰的に分解して、最小の部分問題 \(dp[1]\)、\(dp[2]\) で値を返します。これらの解はすでにわかっており、\(dp[1] = 1\)、\(dp[2] = 2\) です。これは \(1\) 段目、\(2\) 段目までの登り方がそれぞれ \(1\) 通り、\(2\) 通りあることを表します。

図 14-3   階段の登り方を求める再帰木

図解 14-3：階段の上り方を全探索するときの重複部分問題

dp[9] から素朴な再帰で上から下へ分解すると、同じ部分問題でも結果を共有しないため、異なる枝で繰り返し展開して解くことになります。

階段を 1 歩で 1 段または 2 段上る問題で、dp[i] は i 段目までの上り方の数です。全探索では漸化式 dp[i] = dp[i − 1] + dp[i − 2] に従って再帰的に分解し、基本ケース dp[1] = 1 または dp[2] = 2 に達するまで続けます。

dp[9] を求めるには、まず dp[8] と dp[7] を求めます。dp[8] を求めるときも dp[7] と dp[6] を求めます。全探索の木に現れる 2 つの dp[7] は計算結果を共有せず、現れるたびに個別に展開して解き直します。

14.1.2   方法 2：メモ化探索¶

効率を上げるには、重複する部分問題をそれぞれ 1 回だけ計算するようにしたいところです。そこで配列 mem に各部分問題の解を記録し、探索中に重複する部分問題を枝刈りします。

  1. 初めて \(dp[i]\) を計算したら、後で使えるように mem[i] に記録します。
  2. 再び \(dp[i]\) が必要になったら、mem[i] から結果を直接取得し、この部分問題の再計算を省けます。

コードは次のとおりです。

climbing_stairs_dfs_mem.py
def dfs(i: int, mem: list[int]) -> int:
    """メモ化探索"""
    # 既知の値 dp[1] と dp[2] のうち、該当する方を返す
    if i == 1 or i == 2:
        return i
    # dp[i] が記録済みなら、その値を返す
    if mem[i] != -1:
        return mem[i]
    # dp[i] = dp[i-1] + dp[i-2]
    count = dfs(i - 1, mem) + dfs(i - 2, mem)
    # dp[i] を記録する
    mem[i] = count
    return count

def climbing_stairs_dfs_mem(n: int) -> int:
    """階段の登り方：メモ化探索"""
    # mem[i] に i 段目までの登り方の総数を記録する。-1 は未記録を表す
    mem = [-1] * (n + 1)
    return dfs(n, mem)

ここでも、1 歩で 1 段または 2 段上るときの階段の上り方の数を求めます。基本ケースは dp[1] = 1 と dp[2] = 2 です。メモ化探索では、基本ケース以外で計算した状態の値を配列 mem に保存します。基本ケースならすぐに値を返します。それ以外ならまず記録を調べ、未記録のときだけさらに下へ展開します。

14.1.3   方法 3：動的計画法¶

メモ化探索はトップダウンの手法です。元の問題（根ノード）から出発し、大きな部分問題を小さな部分問題に再帰的に分解して、解がわかっている最小の部分問題（葉ノード）に到達します。そこから再帰を戻りながら各段階の解を集め、元の問題の解を構成します。

逆に、動的計画法はボトムアップの手法です。最小の部分問題の解から出発し、反復によってより大きな部分問題の解を順に構成し、元の問題の解に到達します。

動的計画法では再帰を戻る過程がないので、再帰を使わずループだけで実装できます。次のコードでは、部分問題の解を保存する配列 dp を初期化します。これはメモ化探索の配列 mem と同じ記録の役割を果たします。

ここまでの内容をもとに、動的計画法でよく使う用語を整理しましょう。

  • 配列 dp をdp テーブルと呼びます。\(dp[i]\) は状態 \(i\) に対応する部分問題の解を表します。
  • 最小の部分問題に対応する状態（\(1\) 段目と \(2\) 段目）を初期状態と呼びます。
  • 漸化式 \(dp[i] = dp[i-1] + dp[i-2]\) を状態遷移式と呼びます。

14.1.4   使用メモリの削減¶

すでに気づいた方もいるでしょう。\(dp[i]\) は \(dp[i-1]\) と \(dp[i-2]\) だけで決まるため、すべての部分問題の解を配列 dp に保存する必要はありません。2 つの変数を順次更新すれば十分です。コードは次のとおりです。

        return n
    a, b = 1, 2
    for _ in range(3, n + 1):
        a, b = b, a + b
    return b

    // 状態遷移：小さな部分問題から順に大きな部分問題を解く
    for i := 3; i <= n; i++ {
        a, b = b, a+b
    }
    return b
}

このコードでは配列 dp の領域が不要になり、空間計算量は \(O(n)\) から \(O(1)\) に下がります。

動的計画法では、現在の状態が直前の限られた数の状態だけに依存することがよくあります。その場合は必要な状態だけを残し、次元を減らしてメモリを節約できます。この手法を「ローリング変数」または「ローリング配列」と呼びます。
