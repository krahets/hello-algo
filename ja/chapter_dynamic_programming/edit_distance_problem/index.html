14.6   編集距離問題¶

編集距離はレーベンシュタイン距離（Levenshtein 距離）とも呼ばれ、一方の文字列をもう一方に変えるのに必要な最少の編集回数を指します。情報検索や自然言語処理では、2 つの列の類似度を測るためによく使われます。

問題

2 つの文字列 \(s\) と \(t\) を受け取り、\(s\) を \(t\) に変換するのに必要な最少編集回数を返してください。

文字列に対してできる編集操作は、1 文字の挿入、1 文字の削除、1 文字を任意の 1 文字に置き換える置換の 3 種類です。

図 14-27 のように、kitten から sitting への変換には置換 2 回と追加 1 回の計 3 回、hello から algo への変換には置換 2 回と削除 1 回の計 3 回の編集が必要です。

1.   動的計画法の考え方¶

手順 1：各段階の選択を考え、状態を定義して \(dp\) テーブルを作る

各段階で、文字列 \(s\) に適用する編集操作を 1 つ選びます。

部分問題を作るには、編集に伴って問題が小さくなるように考えます。文字列 \(s\) と \(t\) の長さをそれぞれ \(n\)、\(m\) とし、まず末尾の文字 \(s[n-1]\) と \(t[m-1]\) に注目します。

  • \(s[n-1]\) と \(t[m-1]\) が同じなら、この 2 文字を飛ばして \(s[n-2]\) と \(t[m-2]\) を考えられます。
  • \(s[n-1]\) と \(t[m-1]\) が異なるなら、\(s\) に 1 回の編集（挿入、削除、置換）を施します。末尾を一致させれば、一致した文字を飛ばしてより小さな問題に進めます。

つまり、文字列 \(s\) に対する各段階の選択（編集操作）によって、\(s\) と \(t\) でまだ照合が必要な文字が変わります。そこで状態を、現在 \(s\) と \(t\) で考えている \(i\) 番目と \(j\) 番目の文字に対応させ、\([i, j]\) と表します。

状態 \([i, j]\) の部分問題は、\(s\) の先頭 \(i\) 文字を \(t\) の先頭 \(j\) 文字に変えるための最少編集回数を求めることです。

これで、大きさ \((n+1) \times (m+1)\) の 2 次元の \(dp\) テーブルが得られます。

手順 2：最適部分構造を見つけ、状態遷移式を導く

部分問題 \(dp[i, j]\) に対応する 2 つの文字列の末尾は \(s[i-1]\) と \(t[j-1]\) です。編集操作に応じて、図 14-29 の 3 通りに分けられます。

  1. \(s[i-1]\) の直後に \(t[j-1]\) を追加すると、残る部分問題は \(dp[i, j-1]\) です。
  2. \(s[i-1]\) を削除すると、残る部分問題は \(dp[i-1, j]\) です。
  3. \(s[i-1]\) を \(t[j-1]\) に置換すると、残る部分問題は \(dp[i-1, j-1]\) です。

図 14-29   編集距離の状態遷移

図解 14-29：編集距離の状態遷移

book を code に変える例で、末尾の k と e が異なるとき、追加・削除・置換によってどの接頭辞の部分問題が残るかを 3 通り示します。

dp[i, j] を変換元 s の先頭 i 文字から目標 t の先頭 j 文字への最少編集回数とします。追加、削除、置換のコストはそれぞれ 1 です。図では s = book、t = code（現在の接頭辞長 i = 4、j = 4）を例に、末尾の s[i-1] = k と t[j-1] = e が異なるときの遷移元を示します。

左に現在の状態 dp[i, j] があり、右に上から挿入（追加）、削除、置換の 3 分岐があります。灰色の末尾文字は照合または削除が済み、残りの接頭辞には含めません。

挿入すると、追加した文字と目標の末尾が一致して照合が済みます。元の文字は消費しないので j だけが 1 減ります。削除では変換元の末尾だけを除くため i だけが 1 減ります。置換では両方の末尾が一致して照合が済むので、i と j がともに 1 減ります。

下表は 3 つの分岐の順に、「操作後の変換元」と「残る変換元の接頭辞」を区別し、対応する子状態を示します。この図では book から code までの最終的な編集距離は計算していません。

末尾が異なるときの 3 種類の操作と残る接頭辞
操作操作後の変換元残る変換元の接頭辞残る目標の接頭辞子状態
e を挿入bookebookcoddp[i,j-1]
k を削除booboocodedp[i-1,j]
k を e に置換booeboocoddp[i-1,j-1]

どの操作にも 1 回かかるので、残る部分問題の編集回数が最も少ないものを選びます。したがって末尾の文字が異なるときは dp[i,j] = min(dp[i,j-1], dp[i-1,j], dp[i-1,j-1]) + 1 です。

以上から最適部分構造がわかります。\(dp[i, j]\) の最少編集回数は、\(dp[i, j-1]\)、\(dp[i-1, j]\)、\(dp[i-1, j-1]\) の最少編集回数のうち最も小さい値に、今回の編集回数 \(1\) を加えた値です。対応する状態遷移式は次のとおりです。

\[ dp[i, j] = \min(dp[i, j-1], dp[i-1, j], dp[i-1, j-1]) + 1 \]

ただし、\(s[i-1]\) と \(t[j-1]\) が同じ場合は、この文字を編集する必要はありません。この場合の状態遷移式は次のとおりです。

\[ dp[i, j] = dp[i-1, j-1] \]

手順 3：境界条件と状態遷移の順序を決める

両方の文字列が空なら、編集回数は \(0\)、つまり \(dp[0, 0] = 0\) です。\(s\) が空で \(t\) が空でなければ、最少編集回数は \(t\) の長さに等しく、先頭行は \(dp[0, j] = j\) となります。\(s\) が空でなく \(t\) が空なら、最少編集回数は \(s\) の長さに等しく、先頭列は \(dp[i, 0] = i\) となります。

状態遷移式を見ると、解 \(dp[i, j]\) は左、上、左上の解に依存します。したがって、二重ループで \(dp\) テーブル全体を先頭から順に走査すれば十分です。

2.   実装¶

edit_distance.py
def edit_distance_dp(s: str, t: str) -> int:
    """編集距離：動的計画法"""
    n, m = len(s), len(t)
    dp = [[0] * (m + 1) for _ in range(n + 1)]
    # 状態遷移：先頭行と先頭列
    for i in range(1, n + 1):
        dp[i][0] = i
    for j in range(1, m + 1):
        dp[0][j] = j
    # 状態遷移：残りの行と列
    for i in range(1, n + 1):
        for j in range(1, m + 1):
            if s[i - 1] == t[j - 1]:
                # 2 文字が等しければ、両方とも読み飛ばす
                dp[i][j] = dp[i - 1][j - 1]
            else:
                # 最少編集回数 = 挿入・削除・置換の各場合の編集回数の最小値 + 1
                dp[i][j] = min(dp[i][j - 1], dp[i - 1][j], dp[i - 1][j - 1]) + 1
    return dp[n][m]

int EditDistanceDP(string s, string t) {
    int n = s.Length, m = t.Length;
    int[,] dp = new int[n + 1, m + 1];
    // 状態遷移：先頭行と先頭列
    for (int i = 1; i <= n; i++) {
        dp[i, 0] = i;
    }
    for (int j = 1; j <= m; j++) {
        dp[0, j] = j;
    }
    // 状態遷移：残りの行と列
    for (int i = 1; i <= n; i++) {
        for (int j = 1; j <= m; j++) {
            if (s[i - 1] == t[j - 1]) {
                // 2 文字が等しければ、両方とも読み飛ばす
                dp[i, j] = dp[i - 1, j - 1];

                // 最少編集回数 = 挿入・削除・置換の各場合の編集回数の最小値 + 1
                dp[i, j] = Math.Min(Math.Min(dp[i, j - 1], dp[i - 1, j]), dp[i - 1, j - 1]) + 1;
            }
        }
    }
    return dp[n, m];

図解 14-30：動的計画法で求める編集距離

変換元と変換先の接頭辞の組ごとに表を 1 マスずつ埋め、文字列 bag を pack に変えるための最少編集回数を求めます。

変換元の文字列 s は bag（長さ 3）、変換先の文字列 t は pack（長さ 4）です。この図の入力は本文のほかの例とは異なります。1 回の操作で 1 文字を挿入、削除、または置換でき、どの操作のコストも 1 です。

状態 dp[i, j] は、変換元 s の先頭 i 文字（変換元の接頭辞）を変換先 t の先頭 j 文字（変換先の接頭辞）に変えるのに必要な最少編集回数です。二次元の表は 4 行 5 列です。行 i = 0 から 3 は順に変換元の接頭辞である空文字列、b、ba、bag に対応し、列 j = 0 から 4 は順に変換先の接頭辞である空文字列、p、pa、pac、pack に対応します。

まず 4×5 の全マスを 0 にした表を作ります。この時点で dp[0, 0] の 0 は、空文字列を空文字列に変えるときの有効な境界値です。次に、先頭行の長さが正のマスを dp[0, j] = j とします。空文字列に j 文字を続けて挿入すれば、変換先の接頭辞になるためです。先頭列の長さが正のマスは dp[i, 0] = i とします。変換元の接頭辞から i 文字を続けて削除すれば、空文字列になるためです。内部の残り 12 マスは上の行から下へ、各行では左から右へ順に求めます。

3.   使用メモリの削減¶

\(dp[i,j]\) は上の \(dp[i-1, j]\)、左の \(dp[i, j-1]\)、左上の \(dp[i-1, j-1]\) から求めます。しかし、昇順に走査すると左上の \(dp[i-1, j-1]\) が失われ、降順に走査すると \(dp[i, j-1]\) を先に求められません。そのままではどちらの順序も使えません。

そこで変数 leftup に左上の解 \(dp[i-1, j-1]\) を一時保存しておけば、あとは左と上の解だけを考えれば済みます。個数制限なしナップサック問題と同じ状況になり、昇順に走査できます。コードは次のとおりです。

def edit_distance_dp_comp(s: str, t: str) -> int:
    """編集距離：使用メモリを削減した動的計画法"""
    n, m = len(s), len(t)
    dp = [0] * (m + 1)
    # 状態遷移：先頭行
    for j in range(1, m + 1):
        dp[j] = j
    # 状態遷移：残りの行
    for i in range(1, n + 1):
        # 状態遷移：先頭列
        leftup = dp[0]  # dp[i-1, j-1] を一時保存する
        dp[0] += 1
        # 状態遷移：残りの列
        for j in range(1, m + 1):
            temp = dp[j]
            if s[i - 1] == t[j - 1]:
                # 2 文字が等しければ、両方とも読み飛ばす
                dp[j] = leftup
            else:
                # 最少編集回数 = 挿入・削除・置換の各場合の編集回数の最小値 + 1
                dp[j] = min(dp[j - 1], dp[j], leftup) + 1
            leftup = temp  # 次の反復で使う dp[i-1, j-1] に更新する
    return dp[m]
