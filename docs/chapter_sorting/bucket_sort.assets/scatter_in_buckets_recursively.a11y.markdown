# 递归拆分数据过多的价格桶

先将商品粗分为三个价格桶，再递归拆分占比 65% 与 35% 的密集桶，得到七个较均衡的叶桶。

## 问题与输入

每个桶标注的“数据占比”均指占全部商品数据的百分比，而非占其父桶的比例。图中仅给出价格区间简写与数据占比，未指定商品总数、货币单位或边界点的开闭归属。

## 结构与关系

第一层粗分将商品数据划分为三个价格桶：&lt;100 占 65%，100–500 占 20%，&gt;500 占 15%。由于 &lt;100 桶集中了 65% 的数据，继续将该桶向下细分为三个子桶。

第二层将 &lt;100 桶拆分为：&lt;10 占 18%，10–50 占 35%，50–100 占 12%，三项之和恰好等于父桶的 65%。其中 10–50 桶占比仍明显偏高（35%），因此再向下一层细分为 10–20 占 13%、20–35 占 12%、35–50 占 10%，三项之和等于 35%。

画面右侧“数据划分结果”汇总了递归树的七个叶节点桶（详见附表），各叶桶占比分布在 10% 至 20% 之间，显著比初始的 65%、20%、15% 更均衡。中间层的 65% 和 35% 属于已被拆开的父桶汇总，不再计入最终结果桶。

## 针对高占比桶按需递归细分

从顶部“商品数据”出发的分支箭头表示对高密度价格桶的递归拆解：先拆开占 65% 的 &lt;100 桶，再拆开其中占 35% 的 10–50 桶，其余占比适中的桶则直接作为叶节点保留。

## 结果

最终保留的七个叶桶占比合计为 100%，通过按需递归细分密集区间，使各桶的数据量趋于均匀。图中价格区间采用简写形式，实际编码时仍需明确区间端点的开闭约定。
