# 算法 A、B 和 C：时间长短与增长趋势

算法 A 与 C 的打印次数固定不变，同属常数阶 O(1)；算法 B 的打印次数随输入规模 n 线性增长，属线性阶 O(n)。

## 问题与输入

设输入数据大小为 n，三个算法执行同一种打印操作：算法 A 只打印 1 次，算法 B 循环打印 n 次，算法 C 循环打印 1000000 次。

坐标图横轴表示输入数据大小 n，标有刻度 0 至 9；纵轴表示算法运行时间，自下而上可见刻度为 0、5、10、竖向省略号与 1000000。

## 结构与关系

图中用三条不同颜色的线条对比运行时间的变化走势：绿色直线“算法 A — 常数阶”紧贴横轴上方（位于刻度 0 与 5 之间，对应 1 次操作），橙色直线“算法 C — 常数阶”位于纵轴高处的刻度 1000000，两条水平线的高度都不随 n 增大而改变。

蓝色斜线“算法 B — 线性阶”从横轴 0 处的高度 0 出发，在 n = 1 处与绿色 A 线相交，随后随 n 增大向右上方均匀上升，在 n = 9 处升至刻度 10 附近。由于纵轴在刻度 10 与 1000000 之间用省略号压缩了巨大跨度，不能直接按画面上的垂直距离测算真实时间比例。

算法 A（1 次打印）与算法 C（1000000 次打印）耗时相差极大，但两者的操作数量都与输入规模 n 无关，增长趋势相同，因此时间复杂度均为常数阶 O(1)。算法 B 的打印次数与 n 成正比，时间复杂度为线性阶 O(n)：在图中 n = 0 至 9 的小规模区间内，B 的耗时远低于 C；但当 n 超过 1000000 时，B 的操作数量就会反超 C。

## 结果

时间复杂度衡量的是运行时间随数据规模 n 增大的渐近增长趋势，而非固定输入下的实际耗时。在本例同一种打印操作的计数模型下，当 n 超过 1000000，B 的操作次数就会超过 A 和 C；但同为常数阶 O(1) 的算法 A 和算法 C，实际运行时间仍可能相差悬殊。
