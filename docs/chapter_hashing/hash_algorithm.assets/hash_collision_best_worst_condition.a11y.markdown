# 链式地址哈希表的最佳分布与最差退化对比

对比六个键值对 (k₁, s₁) 至 (k₆, s₆) 在链式地址哈希表中的两种极端分布：均匀分散到各桶时查询时间复杂度为 O(1)，全部冲突集中到单个桶时退化为 O(n)。

## 问题与输入

画面左上方总标题为“链式地址哈希表”，上下并列两个浅绿色面板，分别展示同一批六个键值对 (k₁, s₁) 至 (k₆, s₆) 的最佳情况与最差情况。

每个面板左侧的浅蓝色竖栏表示桶数组（包含每个非空桶链表的头节点及代表其余桶的省略号“…”），右侧通过水平箭头表示桶内连接的单向链表节点。

## 结构与关系

上方面板展示“最佳情况：键值对平均分布在各个桶中，时间复杂度 O(1)”。六个键值对均匀分散在三个已画出的桶中：第一个桶连接 (k₁, s₁) → (k₂, s₂)，第二个桶连接 (k₃, s₃) → (k₄, s₄)，第三个桶连接 (k₅, s₅) → (k₆, s₆)。每个桶的链表长度都很短（仅 2 个节点），定位到桶后只需常数次比较即可完成查找。当数据规模增长时，O(1) 查询还需要维持适当的负载因子，使平均链长保持常数量级；仅有分布均匀并不足以无条件保证这一复杂度。

下方面板展示“最差情况：键值对全部分布在单个桶中，时间复杂度 O(n)”。六个键值对的哈希值全部相同，统统落入第一个桶并串成一条长达 6 个节点的单向链表：(k₁, s₁) → (k₂, s₂) → (k₃, s₃) → (k₄, s₄) → (k₅, s₅) → (k₆, s₆)，而下方其余桶全空（以省略号表示）。此时哈希表彻底退化为单向链表，查找末尾元素需要遍历全部 n 个节点。

## 六个键值对的均匀分布 O(1) 与单桶退化 O(n)

对比两图可见，同样存放 (k₁, s₁) 到 (k₆, s₆) 六个键值对：上图将它们平均分配到三个桶，每条链表只有 2 个节点，例如查找 k₆ 只需在第三个桶内检查 k₅ 和 k₆ 两项，查询时间复杂度为 O(1)；下图则把六个键值对全部挤进第一个桶，查找 k₆ 必须从 k₁ 一路顺着链表遍历 6 个节点到链尾，当数据规模为 n 时时间复杂度退化为 O(n)。

## 结果

哈希算法的设计目标正是让键值分布尽量接近上图所示的均匀状态（O(1) 查询），避免出现下图所示所有键扎堆落入同一桶的 O(n) 退化。
