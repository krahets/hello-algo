# 哈希冲突：两个不同学号映射到同一个桶索引

当哈希函数为 key % 100 时，后两位相同的不同学号 20336 与 12836 都会映射到 36 号桶，引发哈希冲突并导致未作冲突处理时误读结果。

## 问题与输入

本图沿用上一图的容量 100 桶数组与哈希函数 key % 100，其中 36 号桶当前存放的是键值对 (12836, “小哈”)。

正文以学号 20336 和 12836 说明两个不同输入的后两位均为 36，因此会映射到同一桶；本图及相关正文没有给出 20336 对应的真实姓名。

## 结构与关系

左侧“输入 key”列从上到下给出橙色 20336 和蓝色 12836。两条有向曲线经过“哈希函数 key % 100”后，在进入索引 36 前汇合到一起，图中在汇合处上方用粉红色标签醒目标注“哈希冲突”。

由于 36 号数组桶只放了一个键值对 (12836, “小哈”)，且此处尚未引入冲突解决机制，橙色路径（查询 20336）与蓝色路径（查询 12836）穿过 36 号桶后，在右侧“输出 value”列双双输出了“小哈”（上方橙色框“小哈”、下方蓝色框“小哈”），直观揭示了直接按哈希值读取而不处理冲突会造成数据张冠李戴。

## 20336 与 12836 在 36 号桶发生哈希冲突

输入学号 20336 和 12836 对 100 取余的结果均为 36，两条路径同时指向 36 号桶并触发“哈希冲突”标注。因为 36 号桶内实际保存的是 (12836, “小哈”)，若不核对完整学号也不做冲突处理，对 20336 的查询就会错误地读到属于 12836 的“小哈”；对 12836 返回“小哈”则与桶内学号匹配。

## 结果

多个不同输入经哈希函数得到相同桶索引的现象称为哈希冲突；哈希表可用链式地址或开放寻址等机制正确区分和存储冲突键，扩容则用于降低负载并缓解冲突。
