# 开放寻址哈希表：步长为 1 的线性探测

不引入额外链表，所有键值对均直接存放在桶数组内；发生哈希冲突时，从起始桶按步长 1 向下线性探测，放入第一个遇到的空桶。

## 问题与输入

左侧说明框标注“开放寻址：线性探测，步长为 1”，下方标注“哈希函数 key % 100；后两位相同的 key 会发生哈希冲突”。

右侧仅有一个一维桶数组，每个槽位最多存放一个键值对。在“索引”列与“数组”列之间，图用两个左花括号分别将上方的 3 个连续桶括向加粗索引 00，将下方的 5 个连续桶括向加粗索引 76，表示这两簇元素各自的哈希起始桶为 00 和 76。

## 结构与关系

第一簇包含后两位均为 00 的三个键 200、500、300：插入 (200, A) 时直接落入起始桶 00；插入 (500, D) 时发现桶 00 已被占用，便按步长 1 向下探测并存入桶 01；插入 (300, Y) 时依次探测过 00、01，最终存入桶 02。

## 起始桶 00 与 76 处的两组线性探测簇

图中两个花括号清晰标出了线性探测的聚集效应：哈希值为 00 的三个键 200、500、300 依次占据连续槽位 00、01、02；哈希值为 76 的五个键 076、876、276、676、776 依次占据从 76 开始的五个连续槽位。例如查找键 276 时，先由 276 % 100 = 76 访问桶 76（存有 076，不匹配），再按步长 1 探测桶 77（存有 876，不匹配），接着探测桶 78 才找到匹配的 (276, E)。

## 结果

在开放寻址的线性探测中，元素的实际数组下标可能排在其哈希起始桶之后；查询时同样必须从 key % 100 对应的起始桶开始，按步长 1 依次向后比对 key。
