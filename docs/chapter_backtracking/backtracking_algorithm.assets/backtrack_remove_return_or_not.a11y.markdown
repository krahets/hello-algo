# 记录解后是否继续搜索

当目标节点的后代中仍可能存在合法解时，记录解后立即返回会漏掉深层解，需删除该提前 return 以继续搜索。

## 问题与输入

任务是寻找从根节点出发、终点值为 7 且路径不含 3 的所有路径。图中二叉树共有 8 个节点：根为 1，左、右子节点为 7 和 3；左侧 7 的左、右子节点为 4 和 5，且 4 下方还有一个左子节点 7；3 的左、右子节点为 6 和右侧 7。

这里对比的是“记录解之后是否立即执行 return 结束当前递归分支”。遇到节点 3 时停止深入的剪枝，以及遍历完子节点后的正常回退，在两种做法中均保留不变；框架代码通过拒绝值为 3 的选择来实现这项剪枝。

左图保留记录解后的 return：访问根的左子节点 7 并记录 \[1, 7\] 后立即停止当前分支，剪掉了其下方的节点 4、5 及 4 的左子节点 7，从而漏掉深层解。右图删除该提前 return：记录浅层解 \[1, 7\] 后继续递归访问子节点 4 及其左子节点 7，成功找到第二条合法路径 \[1, 7, 4, 7\]。左右两图在右分支遇到红色节点 3 时均执行剪枝，不会进入 6 和右侧 7。注意本图比前文例题及配套 Python 代码的七节点树多画了节点 4 下方的深层左子节点 7，第二条解 \[1, 7, 4, 7\] 按图中八节点树得出。

## 结果

在这棵八节点树上，保留记录解后的提前 return 只能找到 \[\[1, 7\]\]；删除该提前 return 后可完整找到 \[\[1, 7\], \[1, 7, 4, 7\]\]。
