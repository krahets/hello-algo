# 相等候选造成新的组合重复

候选数组中两个值为 4 的元素，会在同一轮选择中产生内容相同的重复子集分支。

## 问题与输入

图中候选数组为 choices=\[4, 4̂, 5\]，其中 4̂ 表示第二个值为 4 的数组元素。子集和 II 要求每个数组索引最多使用一次且解集不包含重复子集；本图先展示沿用旧选择方式时因相等元素引发的重复现象，尚未施加完整的索引不重用约束。

## 结构与关系

两层局部搜索树从空状态出发，第一轮展开 +4、+4̂、+5 三个分支；第二轮仅在第一个 \[4, …\] 下继续展开 +4、+4̂、+5。两条灰色弯线分别连接第一轮的 \[4, …\] 与 \[4̂, …\]、第二轮的 \[4, 4, …\] 与 \[4, 4̂, …\]，并标注“重复子集”。

<a id="source-361"></a>

第一轮分别选取第一个 4 和第二个 4̂ 时，虽然它们来自不同数组索引，但生成的子集前缀在数值上都是 \[4, …\]，继续搜索会产生完全重复的子集。第二轮在第一个 \[4, …\] 下若按旧方式继续选 +4 和 +4̂，所得 \[4, 4, …\] 与 \[4, 4̂, …\] 同样被标为重复子集；需要注意，其中 \[4, 4, …\] 还重复使用了第一个 4 的同一个索引，这在每个元素仅限用一次的子集和 II 中本身就是非法分支。

## 结果

要解决子集和 II 的重复问题，既要禁止同一索引在一条路径中被重复选取，又要限制同一轮中相等数值的候选只尝试一次；而不同索引的两个 4 仍允许在不同轮次先后入选。
