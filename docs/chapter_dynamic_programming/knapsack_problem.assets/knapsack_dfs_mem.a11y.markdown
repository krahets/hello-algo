# 0-1 背包的记忆化搜索

右分支再次遇到 dp\[1, 10\] 时直接读取缓存返回有效值 60，省去重复子树，并与超重剪枝区分。

## 问题与输入

0-1 背包中每件物品最多选择一次。本图使用与前图相同的独立 3 物品、容量 cap = 30 示例：重量依次为 10、20、20，价值依次为 60、110、120（见表）。dp\[i, c\] 表示前 i 件物品在可用容量 c 下的最大价值；图中表头写 wgt\[i\]、val\[i\]（i 从 1 到 3），正文代码用下标 i-1 访问数组。

当当前物品装得下时，比较不选它的 dp\[i-1, c\] 与选它的 dp\[i-1, c-wgt\[i-1\]\] + val\[i-1\]，取较大值；装不下时只取不选分支。无物品（i = 0）或容量为 0（c = 0）时返回 0。图中的负容量节点仅示意被排除的选择，代码在递归前判断超重，不实际调用负容量状态。

## 结构与关系

从根 dp\[3, 30\] 依次对物品 3、2、1 决策时，由于物品 2（西瓜）和物品 3（菠萝）的重量同为 20，走“不选物品 3、再选物品 2”或“选物品 3、再不选物品 2”这两条路线都会剩下容量 10、待选范围只剩物品 1（苹果，重 10、价值 60），从而汇合到同一个状态 dp\[1, 10\]。

左子树首次访问 dp\[1, 10\]（路线“不选3→选2”）时，展开比较 dp\[0, 10\] 与 dp\[0, 0\] + 60 并把结果存入缓存；当右子树在 dp\[2, 10\] 下选择不放物品 2、再次遇到 dp\[1, 10\]（路线“选3→不选2”）时，触发“剪枝：找到记录”，直接读取缓存返回，不再重复展开两个叶节点。由物品 1 重 10、价值 60 可推知该缓存返回值为 60，这一数值由输入表推导而来，并非节点上的原标数字。

在右子树 dp\[2, 10\] 处，两个分支虽都带有剪刀标记，但停止原因完全不同：左分支 dp\[1, 10\] 是命中缓存、直接返回合法子问题的有效解 60；右分支 dp\[1, -10\]（“剪枝：物品重量 &gt; 背包容量”）则是因为物品 2 重量 20 超过当前剩余容量 10 而被排除的非法示意节点，程序在递归前已判断超重，只调用不选分支 dp\[1, 10\]，不会实际调用 dp\[1, -10\]。

## 缓存命中复用 dp\[1, 10\] 并与超重剪枝区分

左子树首次求出 dp\[1, 10\] = 60 后写入缓存；右子树在 dp\[2, 10\] 下再次请求 dp\[1, 10\] 时直接读取缓存值 60 返回，省去两个基例叶节点的展开，而旁边的 dp\[1, -10\] 则是因物品 2 超重被排除的示意分支。

## 结果

引入记忆化缓存后，第二处 dp\[1, 10\] 直接复用已算出的有效返回值 60，使图中 i = 0 的基例叶节点由 6 个减少为 4 个（全树共 11 个节点）；按图中输入推算，全局最大价值仍为选物品 1 和物品 3 所得的 180（60 与 180 均为根据输入推导的数值）。
