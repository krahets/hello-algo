# 汉诺塔递归树：两个较小任务加一次单盘移动

每个 f(n) 拆分为左 f(n−1)、中 f(1)、右 f(n−1)，逐层展开至单盘移动 f(1)，总时间呈指数增长。

## 问题与输入

节点 f(k) 表示移动 k 张圆盘的子问题规模。每个规模大于 1 的问题都拆解为：先移走上方 k−1 张盘、再移动底部 1 张最大盘、最后将 k−1 张盘移到目标柱。图中节点仅标注问题规模，未标出各子问题不同的起始柱、缓冲柱和目标柱。

## 结构与关系

递归树顶部为原问题 f(n)，向下一层从左到右分出三个子节点：f(n−1)、f(1)、f(n−1)。其中左右两个绿色节点 f(n−1) 各自再向下分出 f(n−2)、f(1)、f(n−2)，而中间的青色节点 f(1) 已是只需一次单盘移动的最小子问题，不再向下拆分。

图中绿色方框代表仍需继续递归拆解的子问题，青色方框代表直接执行单盘移动的基例 f(1)。中间层以省略号“…”概括，底层全部归结为青色节点 f(1)；注意本图是任意规模 n 的结构示意，不能直接清点图上画出的青色框个数当作某个具体 n 的总移动次数。

按递推关系 T(1) = 1、T(n) = 2T(n−1) + 1 展开，单盘移动总次数为 2^n − 1，因此时间复杂度为 O(2^n)；而同一时刻处于活动状态的递归调用链最长沿 f(n) → f(n−1) → … → f(1) 深入 n 层，因此栈帧空间复杂度为 O(n)。

还需注意，图中每一层中间画出的青色节点 f(1) 代表概念上的单盘移动子任务；在配套代码实现中，这一步直接调用 move 函数移动圆盘，并未额外发起一次 dfs(1) 递归调用，因此本图展示的是问题分解树而非逐条函数调用的精确栈追踪。

每一层非基本子问题都向下分裂出左右两个规模减 1 的子问题和中间一次单盘移动 f(1)，直观展现 O(2^n) 时间复杂度与 O(n) 递归深度的来源。

## 结果

由于每次分解都会产生两个规模仅减 1 的子问题，汉诺塔的递归树节点总数以 O(2^n) 指数级增长，但递归栈深度始终保持为线性的 O(n)。
