# 把一次冒泡排序拆成两个较小排序任务

对比直接冒泡排序八个元素与先二分再分别冒泡排序后合并，二者结果相同，且单次划分后仍为平方阶。

## 问题与输入

左右两条对比路线的共同输入为 \[7, 3, 2, 6, 0, 1, 5, 4\]，共同排序目标为 \[0, 1, 2, 3, 4, 5, 6, 7\]。设数组长度为 n，本图通过复杂度表达式对比划分前后的操作量构成，并未提供实测耗时数据。

## 结构与关系

左侧路线直接对长度为 n 的完整数组执行冒泡排序，标注时间开销为 O(n²)，底部输出升序数组 \[0, 1, 2, 3, 4, 5, 6, 7\]。

右侧路线先将原数组从中点划分为左半 \[7, 3, 2, 6\] 和右半 \[0, 1, 5, 4\]，图中标注“划分 O(n)”；随后对两个长度为 n/2 的子数组分别执行冒泡排序，各自标注“冒泡排序 O((n/2)²)”，得到有序左半 \[2, 3, 6, 7\] 与有序右半 \[0, 1, 4, 5\]；最后执行“合并 O(n)”，交错取出两侧较小元素合成 \[0, 1, 2, 3, 4, 5, 6, 7\]。

右侧合并阶段的交叉箭头表明两个有序半区的元素需按大小穿插归并，而非简单前后拼接。画面底部将右侧总复杂度汇总为“总体 O(n²/2 + 2n)”，对应两次半规模冒泡排序加上线性划分与合并。

右侧路线用额外的线性划分 O(n) 与合并 O(n) 换取两次半规模的冒泡排序 O((n/2)²)，直观解释了将大问题拆分为小问题为何可能减少操作数量。

## 结果

在图中用于比较工作量的简化表达式中，单次中点划分将平方项写为 n²/2，并增加 2n 的划分与合并项，说明分解子问题可能缩减平方主导项的常数系数；但由于只划分了一次，O(n²/2 + 2n) 在渐近意义下仍属于 O(n²)，不能据此声称已降至 O(n log n)，也不能将渐近记号当作精确操作次数或保证实际耗时减半。
