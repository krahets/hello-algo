# 哈希表求两数之和

遍历 nums = \[2, 7, 11, 15\]，依次将 2:0、7:1 存入哈希表 map；访问 11 时查到补数 2 已在表中，直接返回 \[0, 2\]。

## 问题与输入

给定整数数组 nums = \[2, 7, 11, 15\]（索引从 0 到 3）与目标和 target = 13。

借助辅助哈希表 map 记录已遍历过的元素：键（key，标有“元素”）存数组元素值，值（value，标有“索引”）存该元素对应的数组索引。单层循环每轮先查询补数 target − nums\[i\] 是否已在 map 中：若存在则立即返回 \[map\[target − nums\[i\]\], i\]；若不存在才将当前键值对 nums\[i\]: i 写入 map。

## 结构与关系

每轮“先查补数、后存当前元素”的顺序保证了配对的另一个元素必定来自当前位置 i 之前的不同索引。三幅分步画面依次展示 i = 0、1、2 时的判断与哈希表状态（注意第 1 步画面展示的是完成首次插入 2 → 0 之后的状态，而非空表）。

## 第 3 步：找到补数 2，返回索引

指针 i = 2 指向元素 11，图右侧说明“∵ 13 – 11 = 2 在 map 中 ∴ 返回元素组合索引 \[0, 2\]”。哈希表中键 2 对应的索引 value 为 0，与当前索引 i = 2 组成答案 \[0, 2\] 直接返回，不再将 11 写入表中。

<details><summary>本步完整状态</summary><p>数组 nums=[2,7,11,15]，索引从 0 到 3，目标和 target=13。i=2，当前值 11；补数 2 已存在，map[2]=0；返回 [0,2]。map 仍为 {2:0,7:1}，未加入 11，15 尚未处理且不再需要处理。</p></details>

## 结果

当 i = 2 访问元素 11 时，补数 13 − 11 = 2 在 map 中命中旧索引 0，立即返回 \[0, 2\]；当前元素 11 无须再存入 map，末尾索引 3 的 15 也无须继续遍历。在哈希查询平均为 O(1) 的前提下，哈希优化将平均时间复杂度从 O(n²) 降至 O(n)，辅助空间复杂度为 O(n)，体现了“以空间换时间”的策略。
