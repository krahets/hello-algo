13.3   부분집합의 합 문제¶

13.3.1   중복 원소가 없는 경우¶

Question

양의 정수 배열 nums와 양의 정수 목표값 target이 주어진다. 원소의 합이 target인 조합을 모두 찾아라. 배열에는 중복 원소가 없으며 각 원소는 여러 번 선택할 수 있다. 조합을 리스트로 반환하되 같은 조합을 두 번 넣지 마라.

예를 들어 입력 집합이 \(\{3, 4, 5\}\)이고 목표 정수가 \(9\)이면 해는 \(\{3, 3, 3\}, \{4, 5\}\)이다. 다음 두 가지에 유의하자.

  • 입력 집합의 각 원소를 횟수 제한 없이 반복해서 선택할 수 있다.
  • 부분집합에서는 원소의 순서를 구분하지 않는다. 예를 들어 \(\{4, 5\}\)와 \(\{5, 4\}\)는 같은 부분집합이다.

1.   순열 문제의 풀이 응용¶

순열 문제처럼 부분집합을 만드는 과정도 일련의 선택으로 볼 수 있다. 선택할 때마다 원소의 합을 갱신하고 합이 target과 같아지면 해당 부분집합을 결과 리스트에 기록한다.

순열 문제와 달리 이 문제에서는 같은 원소를 횟수 제한 없이 선택할 수 있다. 따라서 불리언 리스트 selected로 원소의 선택 여부를 기록할 필요가 없다. 순열 문제의 코드를 조금 수정해 첫 풀이를 작성해 보자.

def backtrack(
    state: list[int],
    target: int,
    total: int,
    choices: list[int],
    res: list[list[int]],
):
    """백트래킹: 부분집합의 합 I"""
    # 부분집합의 합이 target과 같으면 해를 기록한다
    if total == target:
        res.append(list(state))
        return
    # 모든 선택지를 순회한다
    for i in range(len(choices)):
        # 가지치기: 부분집합의 합이 target을 초과하면 이 선택을 건너뛴다
        if total + choices[i] > target:
            continue
        # 시도: 원소를 선택하고 원소의 합 total을 갱신한다
        state.append(choices[i])
        # 다음 선택을 진행한다
        backtrack(state, target, total + choices[i], choices, res)
        # 되돌리기: 선택을 취소하고 이전 상태를 복원한다
        state.pop()

func backtrackSubsetSumINaive(total, target int, state, choices *[]int, res *[][]int) {
    // 부분집합의 합이 target과 같으면 해를 기록한다
    if target == total {
        newState := append([]int{}, *state...)
        *res = append(*res, newState)
        return

    // 모든 선택지를 순회한다
    for i := 0; i < len(*choices); i++ {

            continue

    }
}

누적 합 0에서 시작해 3, 4, 5를 더한다. 9를 넘는 분기는 가지치기하지만 서로 중복되는 조합 [4, 5]와 [5, 4]를 모두 출력한다.

2.   중복 부분집합 가지치기¶

탐색 도중에 가지치기로 중복을 제거해 보자. 아래 그림(13-11)처럼 같은 원소들을 다른 순서로 선택할 때 중복 부분집합이 생긴다. 다음 예를 보자.

  1. 첫 번째와 두 번째로 각각 \(3\)과 \(4\)를 선택하면 이 두 원소를 포함하는 부분집합을 모두 생성한다. 이를 \([3, 4, \dots]\)로 표시하자.
  2. 이후 첫 번째로 \(4\)를 선택했다면 두 번째 선택에서는 \(3\)을 건너뛰어야 한다. 여기서 생성될 부분집합 \([4, 3, \dots]\)은 1. 단계에서 생성한 부분집합과 완전히 겹치기 때문이다.

각 층에서는 왼쪽에서 오른쪽 순으로 선택지를 하나씩 시도하므로 오른쪽으로 갈수록 잘라 내는 가지가 많다.

  1. 처음 두 번의 선택으로 \(3\)과 \(5\)를 고르면 부분집합 \([3, 5, \dots]\)을 생성한다.
  2. 처음 두 번의 선택으로 \(4\)와 \(5\)를 고르면 부분집합 \([4, 5, \dots]\)을 생성한다.
  3. 첫 번째로 \(5\)를 고르면 두 번째 선택에서는 \(3\)과 \(4\)를 건너뛰어야 한다. 부분집합 \([5, 3, \dots]\)과 \([5, 4, \dots]\)은 각각 1. 단계와 2. 단계에서 설명한 부분집합과 완전히 겹치기 때문이다.

그림 13-11 설명: 선택 인덱스를 비감소 순서로 제한해 중복 조합 방지

다음 단계에서는 현재 인덱스 i부터 그 뒤에서만 선택한다(아래 코드의 시작 인덱스 start = i). 앞선 인덱스로 돌아가 역순의 중복 조합을 만드는 가지를 잘라 낸다.

후보 배열은 choices = [3, 4, 5](인덱스 0, 1, 2)이다. 각 원소를 반복 선택할 수 있고 부분집합은 원소 순서를 구분하지 않는다. 그림은 선택 순서와 중복 부분집합의 관계를 비교하기 위해 처음 두 단계만 펼쳤다. 세 번째 단계와 목표 합 판정은 생략했다.

조합은 원소의 순서를 구분하지 않는다. 큰 인덱스를 고른 뒤 작은 인덱스로 돌아가면 작은 인덱스부터 고른 경로와 반드시 겹친다. 따라서 4를 고른 뒤에는 3으로 돌아가지 않고, 5를 고른 뒤에는 3이나 4로 돌아가지 않는다.

같은 원소를 반복 선택할 수 있으므로(예: [3, 3, …], [4, 4, …], [5, 5, …]) 이번에 인덱스 i를 고르면 다음 시작점을 i + 1이 아닌 start = i로 설정해야 한다. 그래야 현재 원소를 다시 선택하는 가지가 남는다. 끝의 생략 부호는 이후를 그리지 않았다는 뜻이다. 그림은 선택 순서만 비교하며 목표 합에 도달하거나 초과했는지는 판단하지 않는다.

처음 두 단계의 접두부 아홉 개 중 인덱스가 감소하지 않는 여섯 개를 남긴다. 앞선 인덱스로 돌아가는 세 가지는 잘라 낸다.

정리하면 입력 배열이 \([x_1, x_2, \dots, x_n]\)이고 탐색 과정에서 선택한 순서가 \([x_{i_1}, x_{i_2}, \dots, x_{i_m}]\)일 때 인덱스는 \(i_1 \leq i_2 \leq \dots \leq i_m\)를 만족해야 한다. 이 조건에 어긋나는 순서는 모두 중복을 만들므로 가지치기해야 한다.

3.   코드 구현¶

이를 구현하려면 순회 시작점을 나타내는 변수 start를 초기화한다. \(x_{i}\)를 선택하면 다음 단계에서는 인덱스 \(i\)부터 순회한다. 그러면 선택 순서가 \(i_1 \leq i_2 \leq \dots \leq i_m\)를 만족하므로 같은 부분집합이 두 번 생기지 않는다.

이와 함께 코드를 두 가지 더 개선한다.

  • 탐색 전에 배열 nums를 정렬한다. 선택지를 순회하다가 부분집합의 합이 target을 초과하면 즉시 반복을 끝낸다. 뒤에 있는 원소는 더 커서 합이 반드시 target을 초과하기 때문이다.
  • 원소의 합을 담는 변수 total을 없애고 선택한 값을 target에서 빼는 방식으로 합을 추적한다. target이 \(0\)이 되면 해를 기록한다.

13.3.2   중복 원소가 있는 경우¶

Question

양의 정수 배열 nums와 양의 정수 목표값 target이 주어진다. 원소의 합이 target인 조합을 모두 찾아라. 배열에는 중복 원소가 있을 수 있으며, 각 원소는 한 번만 선택할 수 있다. 조합을 리스트로 반환하되 같은 조합을 두 번 넣지 마라.

앞 문제와 달리 입력 배열에 중복 원소가 있을 수 있어 새로운 문제가 생긴다. 예를 들어 배열이 \([4, \hat{4}, 5]\)이고 목표값이 \(9\)이면 기존 코드는 \([4, 5], [\hat{4}, 5]\)를 출력해 같은 부분집합이 두 번 나온다.

한 선택 단계에서 값이 같은 원소를 여러 번 선택하기 때문에 중복이 생긴다. 아래 그림(13-13)에서 첫 번째 선택지는 세 개이고 그중 두 개의 값이 \(4\)이다. 이 둘이 중복된 탐색 가지를 만들어 같은 부분집합을 출력한다. 마찬가지로 두 번째 선택에서 값이 \(4\)인 두 원소 역시 중복 부분집합을 만든다.

그림 13-13   값이 같은 원소 때문에 생기는 중복 부분집합

그림 13-13 설명: 값이 같은 후보로 인한 새로운 조합 중복

후보 배열에서 값이 4인 두 원소는 같은 선택 단계에서 내용이 같은 부분집합을 만드는 중복 가지를 생성한다.

입력 배열은 choices = [4, 4, 5]이고 인덱스는 차례로 0, 1, 2이다. 아래에서는 인덱스 0과 1을 ‘첫 번째 4’와 ‘두 번째 4’로 구분한다. 그림에서는 두 번째 4 위에 모자 기호를 붙였지만 값은 모두 4이다. 부분집합의 합 II에서는 각 인덱스를 최대 한 번 쓰고 결과에서 중복을 제거해야 한다. 그림은 우선 부분집합의 합 I의 방식대로 다음 단계를 start = i에서 시작해 현재 인덱스를 다시 고를 수 있게 하고, 값이 같은 후보에서 생기는 문제를 보여 준다.

위쪽에 choices가 있다. 두 층만 펼친 탐색 트리는 빈 상태에서 시작한다. 첫 번째 단계에서는 첫 번째 4, 두 번째 4 또는 5를 선택하고 두 번째 단계에서는 [첫 번째 4, …] 아래에서만 세 후보를 더 시도한다. 두 곳 모두 세 번째 가지에는 접두부 없이 +5만 표시되어 있다.

첫 회색 곡선은 [첫 번째 4, …]와 [두 번째 4, …]를 잇는다. 둘째 곡선은 [첫 번째 4, 첫 번째 4, …]와 [첫 번째 4, 두 번째 4, …]를 잇는다. 두 곡선 모두 ‘중복 부분집합’으로 표시되어 있다. 앞 쌍의 값 접두부는 모두 [4, …]이고 뒤 쌍은 모두 [4, 4, …]이다. 첫 번째 4를 다시 고르면 인덱스 0도 재사용하므로 부분집합의 합 II의 규칙에서는 그 자체로 허용되지 않는다.

부분집합의 합 II에서 중복을 피하려면 한 경로에서 같은 인덱스의 재선택을 막고, 한 단계에서 값이 같은 후보는 한 번만 시도해야 한다. 인덱스가 다른 두 4를 서로 다른 단계에서 차례로 고르는 것은 허용된다.

1.   값이 같은 원소 가지치기¶

이 문제를 해결하려면 각 단계에서 같은 값은 한 번만 선택해야 한다. 배열이 정렬되어 값이 같은 원소들이 이웃한다는 점을 이용하면 된다. 한 단계에서 순회 중인 원소의 값이 바로 왼쪽 원소와 같다면 그 값은 이미 시도했으므로 현재 원소를 건너뛴다.

동시에 각 배열 원소를 한 번만 선택해야 한다. 이 제약도 변수 start로 처리할 수 있다. \(x_{i}\)를 선택하면 다음 단계에서는 인덱스 \(i + 1\)부터 뒤로 순회한다. 이렇게 하면 중복 부분집합을 제거하면서 같은 원소를 다시 선택하는 것도 막을 수 있다.

    # 부분집합의 합이 target과 같으면 해를 기록한다
    if target == 0:
        res.append(list(state))
        return
    # 모든 선택지를 순회한다
    # 가지치기 2: start부터 순회하여 같은 부분집합이 중복 생성되는 것을 막는다
    # 가지치기 3: start부터 순회하여 같은 원소를 다시 선택하지 않는다

void backtrack(vector<int> &state, int target, vector<int> &choices, int start, vector<vector<int>> &res) {
    // 부분집합의 합이 target과 같으면 해를 기록한다
    if (target == 0) {
        res.push_back(state);
        return;
    }
    // 모든 선택지를 순회한다
    // 가지치기 2: start부터 순회하여 같은 부분집합이 중복 생성되는 것을 막는다
    // 가지치기 3: start부터 순회하여 같은 원소를 다시 선택하지 않는다
    for (int i = start; i < choices.size(); i++) {
        // 가지치기 1: 부분집합의 합이 target을 초과하면 즉시 반복을 끝낸다
        // 배열이 정렬되어 뒤의 원소가 더 크므로 부분집합의 합이 반드시 target을 초과한다
        if (target - choices[i] < 0) {
            break;
        }
        // 가지치기 4: 왼쪽 원소와 값이 같으면 중복된 탐색 분기이므로 건너뛴다
        if (i > start && choices[i] == choices[i - 1]) {
            continue;
        }
        // 시도: 원소를 선택하고 target과 start를 갱신한다
        state.push_back(choices[i]);

        // 되돌리기: 선택을 취소하고 이전 상태를 복원한다

/* 백트래킹: 부분집합의 합 II */
fun backtrack(
    state: MutableList<Int>,
    target: Int,
    choices: IntArray,
    start: Int,
    res: MutableList<MutableList<Int>?>
) {
    // 부분집합의 합이 target과 같으면 해를 기록한다
    if (target == 0) {
        res.add(state.toMutableList())
        return
    }
    // 모든 선택지를 순회한다
    // 가지치기 2: start부터 순회하여 같은 부분집합이 중복 생성되는 것을 막는다
    // 가지치기 3: start부터 순회하여 같은 원소를 다시 선택하지 않는다
    for (i in start..<choices.size) {
        // 가지치기 1: 부분집합의 합이 target을 초과하면 즉시 반복을 끝낸다
        // 배열이 정렬되어 뒤의 원소가 더 크므로 부분집합의 합이 반드시 target을 초과한다
        if (target - choices[i] < 0) {
            break
        }
        // 가지치기 4: 왼쪽 원소와 값이 같으면 중복된 탐색 분기이므로 건너뛴다
        if (i > start && choices[i] == choices[i - 1]) {
            continue
        }
        // 시도: 원소를 선택하고 target과 start를 갱신한다
        state.add(choices[i])
        // 다음 선택을 진행한다
        backtrack(state, target - choices[i], choices, i + 1, res)
        // 되돌리기: 선택을 취소하고 이전 상태를 복원한다
        state.removeAt(state.size - 1)
    }
}

그림 13-14 설명: 부분집합의 합 II의 네 가지 가지치기

정렬된 배열 [4, 4, 5]에서 합이 9인 부분집합을 찾는다. 네 가지 가지치기를 적용하면 유일한 해 [4, 5]만 남는다.

입력 배열은 choices = [4, 4, 5]이고 인덱스는 차례로 0, 1, 2이다. 아래에서는 인덱스 0과 1을 ‘첫 번째 4’와 ‘두 번째 4’로 구분한다. 원래 그림에서는 두 번째 4 위에 모자 기호를 붙였지만 실제 값은 모두 4이다. 배열은 정렬되어 있고 목표값은 target = 9이다. 원 안의 숫자는 남은 목표값이다.

각 인덱스는 최대 한 번 쓸 수 있으며 부분집합은 순서를 구분하지 않는다. 인덱스 i를 고른 뒤 다음 단계를 start = i + 1에서 시작하면 두 규칙을 함께 적용할 수 있다. 앞선 인덱스로 돌아가지 않고(가지치기 2) 현재 인덱스도 다시 쓰지 않는다(가지치기 3).

루트에서 두 번째 4를 시도하면 i = 1이 start = 0보다 크고 직전 후보와 값이 같으므로 같은 단계의 중복 제거(가지치기 4)가 적용된다. [첫 번째 4]에 들어간 새 호출에서는 start = 1이다. 두 번째 4의 i = 1은 start와 같아 i > start를 만족하지 않으므로 선택할 수 있다. 선택하면 남은 값은 1이고 뒤에 남은 5는 이를 초과하므로 가지치기 1에 따라 바로 break한다.

아래 ‘네 가지 가지치기의 의미’ 표는 그림의 네 종류 가위에 대응하며, 그다음 표는 접두부와 후보를 하나씩 보여 준다. 잘라 낸 가지에는 재귀적으로 들어가지 않는다. 가지치기 2와 3은 start = i + 1로 바로 건너뛰므로 코드는 해당 후보를 반복문에서 하나씩 시도하지 않는다. 그림에는 비교를 위해 표시했다. [첫 번째 4, 두 번째 4]에서 첫 번째 4를 다시 고르는 것은 그림에서 앞선 인덱스로 돌아가는 경우(가지치기 2)로 표시되지만 인덱스 0은 이미 경로에 있기도 하다.
