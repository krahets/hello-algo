14.3   동적 계획법 문제 풀이¶

앞선 두 절에서 동적 계획법 문제의 주요 특성을 알아보았다. 이제 실제로 문제를 풀 때 마주치는 두 가지 질문을 살펴보자.

  1. 동적 계획법으로 풀 문제인지 어떻게 판단하는가?
  2. 동적 계획법 문제는 어디에서 시작해 어떤 순서로 풀어야 하는가?

14.3.1   문제 판별¶

일반적으로 중복되는 부분 문제와 최적 부분 구조가 있고 무후효성을 만족한다면 동적 계획법이 적합하다. 하지만 문제 설명만 보고 이런 특성을 바로 알아내기는 어렵다. 그래서 조건을 조금 완화하여 백트래킹(완전 탐색)으로 풀 수 있는지 먼저 살펴본다.

백트래킹이 적합한 문제는 보통 ‘의사 결정 트리’로 나타낼 수 있다. 각 노드는 하나의 결정을, 각 경로는 일련의 결정을 나타낸다.

다시 말해 무엇을 결정하는지가 명확하고 그러한 결정들이 모여 해가 된다면 의사 결정 트리로 모델링할 수 있으며, 대개 백트래킹으로 풀 수 있다.

여기에 다음과 같은 특징까지 있다면 동적 계획법이 적합할 가능성이 더 높다.

  • 최대나 최소, 가장 많거나 가장 적은 수 등 최적화 목표가 주어진다.
  • 리스트, 다차원 행렬 또는 트리로 상태를 나타낼 수 있고, 한 상태와 주변 상태 사이에 점화 관계가 있다.

반대로 다음과 같은 특징은 동적 계획법이 적합할 가능성을 낮춘다.

  • 최적해 하나를 구하는 것이 아니라 가능한 모든 해를 찾아야 한다.
  • 문제에 순열이나 조합의 특징이 뚜렷하며, 구체적인 방법을 여러 개 반환해야 한다.

문제를 의사 결정 트리로 나타낼 수 있고 동적 계획법에 유리한 특징이 뚜렷하면, 일단 동적 계획법 문제라고 가정하고 풀어 가면서 그 가정을 확인할 수 있다.

14.3.2   문제 풀이 단계¶

동적 계획법의 풀이 과정은 문제의 성격과 난이도에 따라 달라진다. 보통은 각 단계의 결정을 설명하고, 상태를 정의하고, \(dp\) 테이블을 만든 뒤, 상태 전이식을 유도하고 경계 조건을 정한다.

풀이 단계를 구체적으로 살펴보기 위해 대표적인 문제인 ‘최소 경로 합’을 예로 들자.

Question

크기가 \(n \times m\)인 2차원 격자 grid가 주어진다. 각 칸에는 그 칸의 비용을 나타내는 음이 아닌 정수가 들어 있다. 로봇은 왼쪽 위 칸에서 출발해 한 번에 아래나 오른쪽으로 한 칸씩 이동하여 오른쪽 아래 칸에 도달한다. 왼쪽 위에서 오른쪽 아래까지의 최소 경로 합을 반환하라.

아래 그림(14-10)에서 주어진 격자의 최소 경로 합은 \(13\)이다.

그림 14-10 설명: 4×4 격자의 최소 경로 합

4×4 비용 격자에서 왼쪽 위부터 오른쪽 아래까지 오른쪽이나 아래로만 이동한다. 초록색 최적 경로의 일곱 칸을 더하면 13이다.

4×4 격자 grid의 각 칸에는 그곳을 지날 때 내는 비용이 음이 아닌 정수로 들어 있다. 왼쪽 위 출발점 [0, 0]에서 오른쪽 아래 도착점 [3, 3]까지 한 번에 오른쪽이나 아래로 한 칸씩 이동한다. 경로 합에는 양 끝 칸도 포함된다(행과 열 인덱스는 0부터 시작).

왼쪽에는 4×4 입력 격자 전체가 있고 왼쪽 위에 ‘출발점’, 오른쪽 아래에 ‘도착점’이 표시되어 있다. 가운데 화살표가 오른쪽의 같은 격자를 가리킨다. 이 격자에는 왼쪽 위부터 오른쪽 아래까지 일곱 칸을 잇는 꺾은 경로가 초록색이다. 아래에는 ‘최소 경로 합은 13이며 최적 경로는 1→2→2→3→2→1→2이다’라고 적혀 있다.

첫 번째 단계: 매번 내릴 결정을 생각하고 상태를 정의해 \(dp\) 테이블 구성하기

이 문제에서 매번 내리는 결정은 현재 칸에서 아래로 한 칸 갈지 오른쪽으로 한 칸 갈지다. 현재 칸의 행과 열 인덱스가 \([i, j]\)이라면 아래나 오른쪽으로 움직인 뒤에는 각각 \([i+1, j]\) 또는 \([i, j+1]\)이 된다. 따라서 상태에는 행 인덱스와 열 인덱스라는 두 변수가 필요하며 이를 \([i, j]\)로 표기한다.

상태 \([i, j]\)의 부분 문제는 출발점 \([0, 0]\)에서 \([i, j]\)까지의 최소 경로 합을 구하는 것이다. 그 해를 \(dp[i, j]\)로 표기한다.

이렇게 하면 아래 그림(14-11)처럼 입력 격자 \(grid\)와 크기가 같은 2차원 \(dp\) 행렬을 얻는다.

그림 14-11   상태 정의와 dp 테이블

그림 14-11 설명: 격자 위치를 2차원 dp 상태로 정의하기

행과 열 좌표 [i, j]로 상태를 정의하고 같은 크기의 4×4 dp 테이블을 만든다. 각 칸은 출발점부터 그 칸까지의 최소 경로 합을 구하는 부분 문제에 대응한다.

입력은 음이 아닌 비용을 담은 4×4 격자 grid다(인덱스 0~3의 전체 값은 표 참조). 왼쪽 위 출발점 [0, 0]에서 한 번에 오른쪽이나 아래로 한 칸씩 이동하며 양 끝 칸도 합에 포함한다. 그림은 원래 격자 grid와 동적 계획법 테이블 dp의 상태 정의를 비교한다.

두 4×4 행렬은 의미가 다르다. grid[i, j]는 한 칸을 지날 때의 비용이고, dp[i, j]는 왼쪽 위 출발점 [0, 0]에서 [i, j]까지 양 끝을 포함한 누적 최소 경로 합이다. 예를 들어 grid[1, 1] = 2는 해당 칸 자체의 비용이므로 dp[1, 1]로 바로 쓸 수 없다. 후자에는 출발점에서 그 칸까지 오는 비용도 포함된다.

grid 옆에는 행 인덱스 i, i+1과 열 인덱스 j, j+1이 있다. 현재 칸 [1, 1](비용 2)에서 오른쪽으로 가면 열 인덱스가 1 늘어 [1, 2](즉 [i, j+1], 비용 4)가 된다. 아래로 가면 행 인덱스가 1 늘어 [2, 1](즉 [i+1, j], 비용 3)이 된다. 한 번 움직일 때 행과 열 중 하나만 바뀌므로 상태를 2차원 인덱스 [i, j]로 정의한다.

오른쪽 dp 테이블은 grid와 같은 4×4 행렬로, 행과 열 인덱스는 0~3이다. 각 칸 dp[0, 0]부터 dp[3, 3]까지는 해당 칸까지의 최소 경로 합을 구하는 부분 문제에 대응한다. 여기서는 상태와 좌표의 대응만 정의하고 실제 경로 합은 아직 계산해 넣지 않았다.

행 인덱스열 0열 1열 2열 3

Note

동적 계획법과 백트래킹의 과정은 일련의 결정으로 설명할 수 있다. 상태는 모든 결정 변수로 구성된다. 풀이가 어디까지 진행되었는지를 나타내는 변수를 빠짐없이 담아야 다음 상태를 유도하는 데 필요한 정보가 충분하다.

각 상태는 하나의 부분 문제에 대응한다. 모든 부분 문제의 해를 저장할 \(dp\) 테이블을 정의하면 상태의 각 독립변수가 \(dp\) 테이블의 한 차원이 된다. 본질적으로 \(dp\) 테이블은 상태를 그 부분 문제의 해에 대응시키는 표다.

두 번째 단계: 최적 부분 구조를 찾고 상태 전이식 유도하기

상태 \([i, j]\)로는 위쪽 칸 \([i-1, j]\)과 왼쪽 칸 \([i, j-1]\)에서만 올 수 있다. 따라서 \([i, j]\)까지의 최소 경로 합은 \([i, j-1]\)까지의 최소 경로 합과 \([i-1, j]\)까지의 최소 경로 합 중 작은 쪽으로 결정된다. 이것이 최적 부분 구조다.

이 관계로부터 아래 그림(14-12)의 상태 전이식을 얻는다.

\[ dp[i, j] = \min(dp[i-1, j], dp[i, j-1]) + grid[i, j] \]

그림 14-12 설명: 최소 경로 합의 상태 전이

내부 칸에는 위나 왼쪽에서만 올 수 있으므로 두 선행 칸까지의 누적 최소 경로 합 중 작은 값에 현재 칸의 비용을 더한다.

음이 아닌 수로 이루어진 격자에서 왼쪽 위 [0, 0]을 출발하여 매번 오른쪽이나 아래로 한 칸 이동한다. 출발점과 도착점을 포함해 거친 칸의 값을 더한 것이 경로 합이다. dp[i, j]는 출발점에서 i행 j열까지의 최소 경로 합이다. 행과 열 인덱스는 0부터 시작하며 이 예의 4×4 입력 격자는 표에 있다.

왼쪽에는 원래 4×4 비용 격자 grid, 오른쪽에는 같은 크기의 기호 dp 테이블이 있으며 상태 이름 dp[0, 0]부터 dp[3, 3]까지만 적혀 있다. 왼쪽의 현재 칸 [2, 2](값 2)는 초록색, 바로 위 [1, 2](값 4)는 보라색, 바로 왼쪽 [2, 1](값 3)은 파란색이다. 오른쪽의 대응 상태 dp[2, 2], dp[1, 2], dp[2, 1]도 같은 색이다.

오른쪽 표에는 dp[1, 2]에서 dp[2, 2]로 내려가는 화살표와 dp[2, 1]에서 dp[2, 2]로 향하는 오른쪽 화살표가 있다. 아래의 상태 전이식은 dp[i, j] = min(dp[i-1, j], dp[i, j-1]) + grid[i, j]이다. min은 두 선행 칸까지의 누적 최소 경로 합을 비교한다. 왼쪽 격자에 적힌 한 칸의 비용 4와 3을 비교하는 것이 아니다.

초록색 내부 칸 i=2, j=2에는 위쪽 [1, 2]에서 한 칸 내려오거나 왼쪽 [2, 1]에서 한 칸 오른쪽으로 와야 한다. 따라서 dp[2, 2] = min(dp[1, 2], dp[2, 1]) + grid[2, 2]이며 grid[2, 2]=2이다. 오른쪽 dp 테이블은 기호 사이의 의존 관계만 보여 주며 구체적인 누적값은 아직 비어 있다.

Note

정의한 \(dp\) 테이블을 바탕으로 원래 문제와 부분 문제의 관계를 살펴본다. 부분 문제의 최적해로 원래 문제의 최적해를 구성하는 방법을 찾으면 그것이 최적 부분 구조다.

최적 부분 구조를 찾으면 이를 바탕으로 상태 전이식을 세울 수 있다.

음이 아닌 수로 이루어진 격자에서 [0, 0]부터 출발해 오른쪽이나 아래로만 이동한다. 시작점과 도착점의 값도 경로 합에 포함한다. dp[i, j]는 i행 j열에 도달하는 최소 경로 합이며 행과 열 인덱스는 0부터 3까지이다. 그림의 왼쪽과 오른쪽에는 기호로 채운 4×4 dp 표가 하나씩 있다. 왼쪽은 ‘경계 조건: 첫 행과 첫 열 초기화’를, 오른쪽은 ‘상태 전이 순서: 행렬을 정방향으로 순회’를 설명한다. 구체적인 격자 값은 표시하지 않는다.

왼쪽 그림에서 왼쪽 위 시작점은 초록색, 첫 행의 나머지 칸은 파란색, 첫 열의 나머지 칸은 보라색이다. 화살표는 첫 행을 따라 오른쪽으로, 첫 열을 따라 아래로 향한다. 오른쪽 그림의 화살표는 내부 칸이 이미 준비된 위쪽과 왼쪽 상태에 의존한다는 뜻이다. 두 표 모두 dp[0,0]부터 dp[3,3]까지의 기호만 표시한다.

시작점을 먼저 초기화한 뒤 첫 행과 첫 열은 각각 도달할 수 있는 유일한 방향을 따라 값을 누적한다. 내부 아홉 칸은 바깥 반복문의 행 인덱스 i = 1, 2, 3 순서로, 각 행에서는 안쪽 반복문의 열 인덱스 j = 1, 2, 3 순서로 채운다. 그러면 dp[i,j]를 구할 때 위쪽 dp[i-1,j]는 이전 행에서, 왼쪽 dp[i,j-1]은 현재 행의 왼쪽에서 이미 계산되어 있다. 아래 표의 식은 그림의 경계와 선행 칸 관계를 정리한 것이며 원래 그림에 식이 하나씩 적혀 있는 것은 아니다.

첫 행과 첫 열에서 시작점 이후의 칸에는 이용할 수 있는 선행 칸이 하나뿐이다. 내부 칸에서만 위쪽과 왼쪽 두 선행 칸 중 최솟값을 구한다.

Note

경계 조건은 동적 계획법에서는 \(dp\) 테이블을 초기화하는 데, 탐색에서는 가지치기에 쓰인다.

상태 전이 순서를 정할 때는 현재 문제의 해를 구하는 시점에 그 해가 의존하는 더 작은 부분 문제들이 모두 올바르게 풀려 있도록 해야 한다.

지금까지의 분석만으로도 동적 계획법 코드를 바로 작성할 수 있다. 다만 부분 문제로 나누는 사고 과정은 하향식이므로 ‘완전 탐색 \(\rightarrow\) 메모이제이션 탐색 \(\rightarrow\) 동적 계획법’ 순서로 구현하는 편이 자연스럽다.

1.   방법 1: 완전 탐색¶

상태 \([i, j]\)에서 탐색을 시작해 더 작은 상태 \([i-1, j]\)과 \([i, j-1]\)로 계속 나눈다. 재귀 함수는 다음 요소로 구성된다.

  • 재귀 호출의 매개변수: 상태 \([i, j]\).
  • 반환값: \([0, 0]\)에서 \([i, j]\)까지의 최소 경로 합 \(dp[i, j]\).
  • 종료 조건: \(i = 0\)이고 \(j = 0\)이면 비용 \(grid[0, 0]\)을 반환한다.
  • 가지치기: \(i < 0\)이거나 \(j < 0\)이면 인덱스가 범위를 벗어나므로, 불가능한 경로를 나타내는 비용 \(+\infty\)를 반환한다.

코드는 다음과 같다.

def min_path_sum_dfs(grid: list[list[int]], i: int, j: int) -> int:
    """최소 경로 합: 완전 탐색"""
    # 왼쪽 위 칸이면 탐색을 종료한다
    if i == 0 and j == 0:
        return grid[0][0]
    # 행 또는 열 인덱스가 범위를 벗어나면 비용 +∞를 반환한다
    if i < 0 or j < 0:
        return inf
    # 왼쪽 위에서 (i-1, j)와 (i, j-1)까지의 최소 경로 비용을 구한다
    up = min_path_sum_dfs(grid, i - 1, j)
    left = min_path_sum_dfs(grid, i, j - 1)
    # 왼쪽 위에서 (i, j)까지의 최소 경로 비용을 반환한다
    return min(left, up) + grid[i][j]

그림 14-14   완전 탐색의 재귀 트리

그림 14-14 설명: 최소 경로 합 탐색에서 반복되는 재귀 호출

dp[2,1]에서 선행 상태를 찾을 때 두 호출 경로가 모두 dp[1,0]에 도달한다. 그 서브트리가 두 번 펼쳐지므로 두 번째 탐색은 중복 계산이다.

음이 아닌 수로 이루어진 격자에서 [0, 0]을 출발해 오른쪽이나 아래로만 이동할 수 있다. dp[i, j]는 i행 j열까지의 최소 경로 합이다(인덱스는 0부터 시작한다). 그림은 dp[2, 1]을 루트로 하는 하향식 완전 탐색의 재귀 트리이며 구체적인 격자 가중치는 없다. 재귀는 이전 행과 이전 열의 선행 상태를 거꾸로 찾으므로 실제로 아래나 오른쪽으로 걷는 방향과 반대다.

유효한 내부 상태는 두 선행 상태의 반환값 중 작은 값에 현재 칸의 비용을 더해 구한다. dp[i, j] = min(dp[i-1, j], dp[i, j-1]) + grid[i, j]이다. 출발점에서는 grid[0, 0]을, 음수 인덱스로 범위를 벗어나면 양의 무한대를 반환한다.

재귀 트리의 왼쪽 분기는 이전 행(경로 표기 ‘위’), 오른쪽 분기는 이전 열(‘왼쪽’)을 조회한다. 이 이름은 격자에서 선행 칸이 있는 방향을 뜻하며 화면상의 트리 분기 방향과는 다르다.

루트 dp[2,1]에서 dp[1,1]을 거쳐 dp[1,0]으로 가는 경로는 ‘위→왼쪽’이고, dp[2,0]을 거쳐 dp[1,0]으로 가는 경로는 ‘왼쪽→위’다. 이는 오른쪽 아래의 ‘dp[i+1, j]와 dp[i, j+1]은 모두 dp[i, j]에 의존한다’라는 설명에 해당한다. 이 예에서는 dp[2,0]과 dp[1,1]이 모두 dp[1,0]에 의존한다.

완전 탐색은 이미 푼 상태를 저장하지 않아 두 dp[1,0] 호출에서 각각 자식 dp[0,0]과 dp[1,-1]을 펼친다. 음수 인덱스 노드에는 ‘가지치기: 인덱스 범위 초과’가 적혀 있다. 코드에서는 양의 무한대를 반환해 최솟값을 비교할 때 유효하지 않은 선행 상태를 제외한다.

각 상태에서는 아래와 오른쪽으로 가는 두 가지 선택이 있고, 왼쪽 위에서 오른쪽 아래까지는 총 \(m + n - 2\)걸음이 필요하다. 따라서 최악의 시간 복잡도는 \(O(2^{m + n})\)이다. 여기서 \(n\)과 \(m\)은 각각 격자의 행 수와 열 수다. 이 계산은 격자 경계 부근의 상황을 고려하지 않는다. 경계에 도달하면 선택지가 하나만 남으므로 실제 경로 수는 이보다 적다.

dp[1,0]을 두 번째로 요청하면 캐시에 있는 유효한 경로 합을 바로 읽고 자식을 펼치지 않는다. 이는 범위를 벗어났을 때 양의 무한대를 반환하는 처리와 다르다.

음이 아닌 수로 이루어진 격자에서 [0, 0]을 출발해 오른쪽이나 아래로만 이동한다. dp[i, j]는 i행 j열까지의 최소 경로 합이다(인덱스는 0부터 시작한다). 이번에도 dp[2, 1]을 탐색 루트로 삼아 캐시 mem으로 중복되는 부분 문제를 가지치기하는 과정을 보여 준다. 격자의 구체적인 가중치는 없다. 재귀는 이전 행과 이전 열을 거슬러 조회하므로 실제로 아래나 오른쪽으로 걷는 방향과 반대다.

유효한 내부 상태는 두 선행 상태의 반환값 중 작은 값에 현재 칸의 비용을 더해 구한다. dp[i, j] = min(dp[i-1, j], dp[i, j-1]) + grid[i, j]이다. 출발점에서는 grid[0, 0]을, 음수 인덱스로 범위를 벗어나면 양의 무한대를 반환한다.

재귀 트리의 왼쪽 분기는 이전 행(경로 표기 ‘위’), 오른쪽 분기는 이전 열(‘왼쪽’)을 조회한다. 이 이름은 격자에서 선행 칸이 있는 방향을 뜻하며 화면상의 트리 분기 방향과는 다르다.

루트 dp[2,1]에서 dp[1,1]을 거쳐 dp[1,0]으로 가는 경로는 ‘위→왼쪽’이고, dp[2,0]을 거쳐 dp[1,0]으로 가는 경로는 ‘왼쪽→위’다. 두 경로가 같은 부분 문제를 요청한다.

먼저 dp[1,1] 분기를 푼다. dp[1,0]을 처음 호출하면 두 선행 상태의 반환값을 모두 받은 뒤 현재 칸까지의 최소 경로 합을 구해 mem[1][0]에 저장한다. 그런 다음 그 합을 부모 호출인 dp[1,1]에 반환한다. 이어서 dp[2,0] 분기에서 dp[1,0]을 다시 호출하면 그림의 ‘가지치기: 기록 있음’ 표시처럼 캐시에 저장된 값을 바로 반환한다. 따라서 dp[0,0]과 dp[1,-1]을 다시 호출하지 않는다. dp[2,0]의 다른 자식인 dp[2,-1](‘왼쪽→왼쪽’ 경로)은 인덱스 범위를 벗어나 양의 무한대를 반환한다. 부모 호출은 캐시에서 얻은 유효한 경로 합과 이 양의 무한대 중 작은 값을 선택한다.

이번 탐색의 유효 상태는 0~2행, 0~1열에 있는 [0,0], [0,1], [1,0], [1,1], [2,0], [2,1]이다. dp[0,1]과 처음 계산하는 dp[1,0]은 각각 출발점 dp[0,0]을 한 번 호출하며 경로는 ‘위→위→왼쪽’과 ‘위→왼쪽→위’다. 출발점은 mem을 읽거나 쓰지 않고 grid[0,0]을 바로 반환하므로 출발점 리프 두 개가 남는다. 아래 표는 노드 진입, 위쪽 조회, 왼쪽 조회 순으로 모든 호출을 보여 준다. 별도의 격자나 dp 테이블은 그리지 않았다.

그림 14-16 설명: 최소 경로 합의 동적 계획법

왼쪽 위에서 시작해 첫 행과 첫 열로 가는 유일한 경계 경로의 비용을 먼저 누적한다. 이후 행마다 각 칸의 위쪽 값과 왼쪽 값 중 작은 값에 현재 비용을 더해 오른쪽 아래 도착점까지 계산한다.

4×4 격자 grid에는 음이 아닌 정수 비용이 들어 있다(행과 열 인덱스는 0부터 시작하며 전체 값은 입력 표에 있다). 왼쪽 위 출발점 [0,0]에서 오른쪽 아래 도착점 [3,3]까지 매번 오른쪽이나 아래로 한 칸만 움직인다. 경로 비용에는 출발점과 도착점의 값도 포함된다.

상태 테이블에서 dp[i,j]는 출발점 [0,0]에서 i행 j열까지의 최소 경로 합이다. 표를 만들 때 넣는 0은 아직 계산하지 않은 칸의 초깃값일 뿐, 비용이 0인 경로가 있다는 뜻이 아니다.

경계 초기화: 출발점에 dp[0,0] = grid[0,0] = 1을 기록한다. 0행에는 왼쪽에서 오른쪽으로만, 0열에는 위에서 아래로만 도달할 수 있으므로 첫 행과 첫 열을 따라 비용을 누적해 경계 칸 일곱 개의 유효한 값을 얻는다.

내부 점화: 1~3행과 1~3열이 만나는 내부 아홉 칸을 행마다 왼쪽에서 오른쪽으로 순회하며 dp[i,j] = min(dp[i-1,j], dp[i,j-1]) + grid[i,j]을 계산한다. 이 순서라야 위쪽 dp[i-1,j]와 왼쪽 dp[i,j-1]의 값이 이미 구해져 있다. 각 프레임의 표에는 칸의 값과 함께 ‘계산 전 초깃값’, ‘유효한 경곗값’, ‘계산 완료’ 중 하나가 적혀 있어 좌표로 상태를 확인할 수 있다.

4.   공간 최적화¶

각 칸은 왼쪽 칸과 위쪽 칸에만 의존하므로 한 행짜리 배열 하나로 \(dp\) 테이블을 구현할 수 있다.

배열 dp는 한 행의 상태만 나타낼 수 있다. 따라서 첫 열의 상태를 모두 미리 초기화할 수 없고, 각 행을 순회할 때 해당 값을 갱신해야 한다.

min_path_sum.py
def min_path_sum_dp_comp(grid: list[list[int]]) -> int:
    """최소 경로 합: 공간 최적화 동적 계획법"""
    n, m = len(grid), len(grid[0])
    # dp 테이블 초기화
    dp = [0] * m
    # 상태 전이: 첫 행
    dp[0] = grid[0][0]
    for j in range(1, m):
        dp[j] = dp[j - 1] + grid[0][j]
    # 상태 전이: 나머지 행
    for i in range(1, n):
        # 상태 전이: 첫 열
        dp[0] = dp[0] + grid[i][0]
        # 상태 전이: 나머지 열
        for j in range(1, m):
            dp[j] = min(dp[j - 1], dp[j]) + grid[i][j]
    return dp[m - 1]
