# 2.1 &nbsp; 알고리즘 효율 평가

알고리즘을 설계할 때는 다음 두 목표를 차례로 추구한다.

1. **문제의 해법 찾기**. 정해진 입력 범위 안에서 언제나 올바른 답을 구할 수 있어야 한다.
2. **최적의 해법 찾기**. 한 문제에도 여러 해법이 있을 수 있다. 그중 가능한 한 효율적인 알고리즘을 찾는 것이 목표다.

문제를 올바르게 풀 수 있다는 전제 아래, 알고리즘을 평가하는 주요 기준은 효율이다. 효율에는 다음 두 측면이 있다.

- **시간 효율**은 알고리즘을 실행하는 데 걸리는 시간으로 평가한다.
- **공간 효율**은 알고리즘이 차지하는 메모리 공간의 크기로 평가한다.

요컨대 **빠르면서도 메모리를 적게 쓰는 자료 구조와 알고리즘을 설계하는 것이 목표다**. 그러려면 효율을 제대로 평가할 수 있어야 한다. 그래야 여러 알고리즘을 비교하고 그 결과를 설계와 최적화에 반영할 수 있다.

효율을 평가하는 방법은 크게 실측과 이론적 추정으로 나뉜다.

## 2.1.1 &nbsp; 실측

같은 문제를 풀 수 있는 두 알고리즘 `A`와 `B`의 효율을 비교한다고 하자. 가장 직접적인 방법은 컴퓨터 한 대에서 두 알고리즘을 실행하면서 실행 시간과 메모리 사용량을 측정해 기록하는 것이다. 실제 상황을 반영할 수 있지만 한계도 크다.

첫째, **측정 환경의 영향을 배제하기 어렵다**. 하드웨어 구성이 알고리즘의 성능에 영향을 준다. 예를 들어 병렬화하기 쉬운 알고리즘은 멀티코어 CPU에서 실행하기 좋고, 메모리 연산이 많은 알고리즘은 고성능 메모리를 쓸 때 더 좋은 성능을 낸다. 따라서 같은 알고리즘도 컴퓨터에 따라 측정 결과가 달라질 수 있다. 여러 종류의 컴퓨터에서 측정해 평균을 내야 한다면 현실적으로 쉽지 않다.

둘째, **충분히 다양한 조건에서 측정하려면 자원이 많이 든다**. 입력 크기가 달라지면 알고리즘의 효율도 달라진다. 예를 들어 입력이 작을 때는 알고리즘 `A`가 `B`보다 빨라도 입력이 크면 결과가 정반대일 수 있다. 설득력 있는 결론을 얻으려면 여러 크기의 입력으로 측정해야 하므로 많은 컴퓨팅 자원이 필요하다.

## 2.1.2 &nbsp; 이론적 추정

실측에는 이처럼 한계가 있으므로 계산만으로 효율을 평가하는 방법을 생각해 볼 수 있다. 이를 <u>점근적 복잡도 분석(asymptotic complexity analysis)</u>, 줄여서 <u>복잡도 분석</u>이라고 한다.

복잡도 분석은 알고리즘에 필요한 시간 및 공간 자원과 입력 크기 사이의 관계를 보여 준다. **입력 크기가 커질 때 실행에 필요한 시간과 공간이 어떤 추세로 증가하는지를 나타낸다**. 다소 추상적인 정의이므로 세 부분으로 나누어 보자.

- ‘시간 및 공간 자원’은 각각 <u>시간 복잡도(time complexity)</u>와 <u>공간 복잡도(space complexity)</u>에 대응한다.
- ‘입력 크기가 커질 때’란 복잡도가 알고리즘의 실행 효율과 입력 크기 사이의 관계를 나타낸다는 뜻이다.
- ‘시간과 공간의 증가 추세’란 정확히 몇 초나 몇 바이트가 필요한지보다 시간이나 공간이 얼마나 빠르게 늘어나는지에 주목한다는 뜻이다.

**복잡도 분석은 실측의 한계를 극복한다**. 다음과 같은 장점이 있다.

- 코드를 실제로 실행할 필요가 없어 에너지를 절약할 수 있다.
- 측정 환경에 의존하지 않으므로 분석 결과를 모든 실행 플랫폼에 적용할 수 있다.
- 다양한 입력 크기에서의 효율, 특히 입력이 클 때의 성능을 파악할 수 있다.

!!! tip

    아직 복잡도 개념이 낯설어도 괜찮다. 이어지는 절에서 자세히 살펴본다.

복잡도 분석은 알고리즘의 효율을 평가하는 척도가 된다. 이 척도를 이용해 알고리즘을 실행하는 데 필요한 시간과 공간을 가늠하고 여러 알고리즘의 효율을 비교할 수 있다.

복잡도는 수학적 개념이어서 처음 배울 때는 다소 추상적이고 어려울 수 있다. 그런 점에서는 맨 처음 다루기에 썩 알맞은 주제는 아닐지도 모른다. 하지만 자료 구조나 알고리즘의 특징을 논하려면 실행 속도와 공간 사용량을 분석하는 일을 피하기 어렵다.

따라서 자료 구조와 알고리즘을 깊이 공부하기 전에 **먼저 복잡도 분석의 기초를 익혀 간단한 알고리즘의 복잡도를 스스로 분석할 수 있도록 하자**.
