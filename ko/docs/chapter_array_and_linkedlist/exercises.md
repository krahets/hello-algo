# 연습 문제

## 개념 다지기

### 배열과 연결 리스트에서 원소 찾기

배열과 단일 연결 리스트에 각각 `[A, B, C, D, E]`가 순서대로 저장되어 있다. 이제 네 번째 원소 `D`를 읽으려고 한다.

<!-- numbered-subquestions -->

1. 배열에서는 어느 인덱스로 바로 접근할 수 있는가?
2. 단일 연결 리스트의 머리 노드 `A`에서 시작해 `next`를 따라가면 어떤 노드를 차례로 거치는가?
3. 읽으려는 원소가 뒤쪽에 있을수록 두 구조에서 필요한 단계 수는 각각 어떻게 달라지는가? 위치를 지정해 반복해서 읽는 데 더 적합한 구조는 무엇이며, 그 이유는 무엇인가?

??? success "예시 답안"

    1. 인덱스가 0부터 시작하면 네 번째 원소의 인덱스는 3이므로 배열에서는 `arr[3]`을 바로 읽을 수 있다.

    2. 단일 연결 리스트에서는 반드시 머리에서 시작해야 한다. 경로는 `A → B → C → D`이고, `next`를 따라 세 번 이동해야 한다.

    3. 배열은 시작 주소와 인덱스로 원소의 위치를 바로 계산할 수 있으므로 위치에 따른 접근의 시간 복잡도는 $O(1)$이다.
        단일 연결 리스트의 $k$번째 노드에 접근하려면 머리 노드에서 시작해 `next`를 따라 $k-1$번 이동해야 하며,
        최악의 경우 $O(n)$ 시간이 걸린다.

        여기서는 위치에 따라 값을 읽는 연산만 비교했다. 연결 리스트의 모든 연산이 더 느리다는 뜻은 아니다.

### 배열과 연결 리스트에 원소 삽입하기

배열과 단일 연결 리스트에 각각 `A, B, C, D`가 저장되어 있다. 이제 `B` 뒤에 `X`를 삽입하려고 한다.

- 배열의 용량은 5이고 현재 상태는 `[A, B, C, D, _]`이다.
- 연결 리스트는 `A → B → C → D`이며, 노드 `B`를 가리키는 참조를 이미 가지고 있다.

<!-- numbered-subquestions -->

1. 배열에서 어떤 원소를 옮겨야 하는가? 삽입 후의 배열을 써 보라.
2. 연결 리스트에서 `X.next`와 `B.next`를 어떤 순서로 수정해야 하는가? 삽입 후의 연결 리스트를 써 보라.
3. 삽입 효율을 비교할 때 ‘노드 B의 참조를 이미 가지고 있다’고 명시하는 이유는 무엇인가?

??? success "예시 답안"

    1. 배열에서는 먼저 `D`를 오른쪽으로 한 칸 옮기고, 다음으로 `C`를 오른쪽으로 한 칸 옮긴 뒤, 마지막으로 `X`를 인덱스 2에 넣는다.
        그 결과는 `[A, B, X, C, D]`이다.

    2. 원래 `B.next`는 `C`를 가리킨다. 먼저 `X.next = B.next`로 설정해 `X`가 `C`를 가리키게 한다.
        그다음 `B.next = X`로 설정한다. 결과는 `A → B → X → C → D`이다.
        기존 연결을 저장하지 않고 `B.next`부터 덮어쓰면 `C`를 찾지 못할 수 있다.

    3. `B`의 위치를 이미 알고 있으면 연결 두 개만 바꾸면 되므로 연결 리스트 삽입을 $O(1)$ 시간에 마칠 수 있다.
        머리에서 시작해 `B`를 찾아야 한다면 찾는 데만 $O(n)$ 시간이 걸릴 수 있다.

### 리스트의 용량은 어떻게 늘어나는가?

배열로 구현한 리스트의 현재 내용은 `[A, B, C]`이고, 길이는 `size = 3`, 용량은 `capacity = 4`이다.
용량이 부족하면 기존 배열 용량의 두 배인 새 배열을 만든다고 하자.

<!-- numbered-subquestions -->

1. `D`를 추가한 뒤 리스트의 길이와 용량은 각각 얼마인가? 용량을 늘려야 하는가?
2. 이어서 `E`를 추가하면 용량은 얼마가 되는가? 기존 원소를 몇 개 복사해야 하는가?
3. 내부 배열의 길이는 바뀌지 않는데 리스트의 용량은 어떻게 늘어날 수 있는가?

??? success "예시 답안"

    1. `D`는 마지막 빈자리에 넣을 수 있다. 이때 리스트의 내용은 `[A, B, C, D]`이고,
        `size = 4`, `capacity = 4`이므로 용량을 늘릴 필요가 없다.

    2. 다시 `E`를 추가할 때는 빈자리가 없으므로 용량이 8인 새 배열을 만들고,
        기존 원소 `A, B, C, D` 네 개를 복사한 뒤 `E`를 추가한다.
        이때 `size = 5`, `capacity = 8`이다.

    3. 원래 배열 자체가 길어진 것은 아니다. 리스트는 더 큰 배열을 만들고 기존 원소를 복사한 뒤,
        내부 저장 공간으로 새 배열을 사용한다. 그래서 사용자에게는 용량이 늘어난 것으로 보인다.

### 배열로 표현한 큰 정수에 1 더하기

배열 `digits`에는 음이 아닌 정수의 각 자릿수가 왼쪽부터 차례로 들어 있다. 예를 들어 `[3, 0, 8]`은 308을 나타낸다.
숫자 0은 `[0]`으로 나타낸다. 그 밖의 입력에서는 첫 자릿수가 0인 경우가 없다.

십진수의 세로셈 방식으로 이 정수에 1을 더하고, 결과를 같은 형식의 배열로 반환하라.
`digits`를 직접 수정해도 된다. 맨 앞에서 올림이 발생하면 더 긴 배열을 반환해도 된다.

??? tip "풀이 힌트"

    1. 세로셈으로 더할 때처럼 배열의 마지막 자리부터 시작한다.
    2. 현재 자릿수가 9보다 작으면 1을 더한 뒤 바로 반환할 수 있다.
    3. 현재 자릿수가 9이면 0으로 바꾼다. 모든 자릿수가 9이면 맨 앞에 1을 추가해야 한다.

[LeetCode](https://leetcode.com/problems/plus-one/){ .rounded-button .exercise-button target="_blank" rel="noopener noreferrer" }

### 단일 연결 리스트 뒤집기

단일 연결 리스트의 머리 노드 `head`가 주어진다. 각 노드에는 값과 다음 노드를 가리키는 `next`가 있다.

반복문으로 노드 사이의 모든 연결 방향을 뒤집고, 뒤집은 리스트의 머리 노드를 반환하라.
새 연결 리스트 노드를 생성해서는 안 된다.

??? tip "풀이 힌트"

    1. 먼저 종이에 서로 연결된 노드 세 개와 두 포인터 prev, cur를 그린다.
    2. cur.next를 바꾸기 전에 반드시 원래의 다음 노드를 nxt에 저장한다.
    3. cur.next의 방향을 뒤집은 다음 prev = cur, 이어서 cur = nxt로 설정하고 원래 리스트의 다음 노드를 처리한다.

[LeetCode](https://leetcode.com/problems/reverse-linked-list/){ .rounded-button .exercise-button target="_blank" rel="noopener noreferrer" }
