# 6.5 &nbsp; 연습 문제

## 6.5.1 &nbsp; 개념 다지기

### 1. &nbsp; 해시 충돌이 일어난 뒤에는 어떻게 검색할까?

버킷이 5개인 해시 테이블의 해시 함수는 $h(x)=x \bmod 5$이다. 충돌이 일어나면 해당 버킷의 리스트에 원소를 차례로 넣는다.
`[1, 6, 11, 7]`의 원소를 차례로 삽입한다.

<!-- numbered-subquestions -->

1. 0번부터 4번까지 각 버킷의 내용을 적어 보라.
2. 6을 검색할 때 어느 버킷으로 먼저 가며, 어떤 원소를 어떤 순서로 확인하는가?
3. 1번에서 적은 버킷 내용을 보면 나중에 삽입한 원소가 먼저 삽입한 원소를 덮어썼는가? 이 충돌 처리 방식을 바탕으로 이유를 설명하라.

??? success "예시 답안"

    1. $1\bmod5=6\bmod5=11\bmod5=1$이고 $7\bmod5=2$이므로 각 버킷에 들어가는 원소는 다음과 같다.

        ```text
        0: []
        1: [1, 6, 11]
        2: [7]
        3: []
        4: []
        ```

    2. 6을 검색할 때는 먼저 1번 버킷으로 가서 1, 6과 차례로 비교한다. 두 번째 비교에서 찾는다.

    3. 해시값이 같다는 것은 같은 버킷에 들어간다는 뜻일 뿐, 원소가 같다는 뜻은 아니다. 체이닝은 충돌한 원소를 모두 버킷에 보관하고
        검색할 때 하나씩 비교하므로 1, 6, 11이 서로를 덮어쓰지 않는다.

### 2. &nbsp; 해시 테이블의 용량을 늘리면 원소는 어디로 갈까?

체이닝을 사용하는 해시 테이블에 버킷이 5개 있고 해시 함수는 $h(x)=x\bmod5$이다.
`[1, 6, 11]`에 나열된 키는 모두 1번 버킷에 있다.

이제 버킷을 7개로 늘리면 해시 함수도 $h(x)=x\bmod7$로 바뀐다.

<!-- numbered-subquestions -->

1. 1, 6, 11의 새 버킷 번호를 각각 계산하라.
2. 용량을 늘린 뒤에는 어느 버킷에 원소가 있는가?
3. 기존 1번 버킷의 리스트를 새 1번 버킷에 그대로 복사해도 되는가? 1번과 2번의 결과를 바탕으로 이유를 설명하라.

??? success "예시 답안"

    1. 새 버킷 번호는 각각 다음과 같다.

        - $1\bmod7=1$
        - $6\bmod7=6$
        - $11\bmod7=4$

    2. 1번 버킷에는 1, 4번 버킷에는 11, 6번 버킷에는 6이 저장된다. 세 키가 더 이상 한 버킷에 몰리지 않는다.

    3. 그대로 복사할 수 없다. 버킷 번호는 키를 버킷 수로 나눈 나머지이다. 버킷 수가 5에서 7로 바뀌면 같은 키도 버킷 번호가 달라질 수 있으므로
        각 키의 위치를 다시 계산해야 한다. 기존 1번 버킷을 그대로 복사하면 나중에 새 식으로 6과 11을 검색할 때
        각각 6번 버킷과 4번 버킷으로 가기 때문에 두 키를 찾을 수 없다.

### 3. &nbsp; 6을 삭제한 뒤에도 11을 찾을 수 있을까?

해시 테이블에는 자리가 5개 있고 인덱스 범위는 `0~4`이며 해시 함수는 $h(x)=x\bmod5$이다.
충돌이 일어나면 해시 함수로 계산한 인덱스에서 시작해 오른쪽으로 이동하며 첫 번째 빈자리를 찾는다.

`[1, 6, 11]`의 원소를 차례로 삽입한다.

<!-- numbered-subquestions -->

1. 세 수는 각각 어느 인덱스에 저장되는가?
2. 11을 검색하면 어느 인덱스를 어떤 순서로 확인하는가?
3. 6을 삭제하면서 그 자리를 곧바로 ‘한 번도 사용하지 않은 빈자리’로 바꾸고 검색은 빈자리를 만나는 순간 멈춘다고 하자.
    이때 다시 11을 검색하면 어떻게 되는가? 검색 결과는 올바른가? 문제가 있다면 어떻게 피할 수 있는가?

??? success "예시 답안"

    1. 1은 인덱스 1에 놓인다. 6도 인덱스 1에 대응하지만 충돌이 일어나 인덱스 2에 놓인다.
        11도 인덱스 1에서 시작해 이미 사용 중인 인덱스 1과 2를 차례로 건너뛴 뒤 인덱스 3에 놓인다.

    2. 11을 검색할 때 확인하는 인덱스는 차례로 `1, 2, 3`이며, 인덱스 3에서 찾는다.

    3. 인덱스 2를 ‘한 번도 사용하지 않은’ 빈자리로 바꾸면 11을 검색할 때 인덱스 1을 확인한 뒤 인덱스 2에서 멈추므로
        11이 없다고 잘못 판단한다. 삭제할 때는 그 자리에 ‘삭제됨’ 표시를 남겨야 한다.
        검색 중에 이 표시를 만나면 다음 인덱스를 확인하고, 인덱스 4를 지나면 다시 0으로 돌아간다. 나중에 삽입할 때는 이 자리를 다시 쓸 수 있다.

## 6.5.2 &nbsp; 프로그래밍 연습

### 1. &nbsp; 두 문자열의 문자 구성 비교

영어 소문자로만 이루어진 문자열 두 개 `s`, `t`가 주어진다.
`s`에서 문자의 위치는 마음대로 바꿀 수 있지만 문자를 추가하거나 삭제하거나 다른 문자로 바꿀 수는 없다.

문자의 위치를 바꾸어 `t`를 만들 수 있는지 판단하라. 가능하면 `true`를, 불가능하면 `false`를 반환하라.
문자열의 문자를 정렬하지 말고 해시 테이블로 각 글자의 등장 횟수를 기록하라.

??? tip "풀이 힌트"

    1. 두 문자열의 길이가 다르면 문자 구성도 반드시 다르다.
    2. 해시 테이블에 각 글자의 개수를 기록한다. s를 훑으면서 해당 글자의 개수를 1씩 늘린다.
    3. t를 훑으면서 해당 글자의 개수를 1씩 줄인다. 마지막에 모든 개수가 0이어야 두 문자열의 문자 구성이 같다.
