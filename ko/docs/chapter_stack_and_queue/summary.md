# 5.4 &nbsp; 요약

### 1. &nbsp; 핵심 정리

- 스택은 후입선출 원칙을 따르는 자료 구조로, 배열이나 연결 리스트로 구현할 수 있다.
- 배열로 구현한 스택은 평균적으로 시간 효율이 더 높다. 다만 용량을 늘려야 할 때는 한 번의 푸시 연산에 드는 시간 복잡도가 $O(n)$까지 커진다. 연결 리스트로 구현한 스택은 연산 시간이 더 일정하다.
- 공간 효율을 보면, 배열로 구현한 스택에서는 일부 공간이 낭비될 수 있다. 다만 연결 리스트의 노드 하나가 배열의 원소 하나보다 더 많은 메모리를 차지한다는 점도 고려해야 한다.
- 큐는 선입선출 원칙을 따르는 자료 구조로, 스택과 마찬가지로 배열이나 연결 리스트로 구현할 수 있다. 두 구현 방식의 시간 효율과 공간 효율을 비교하면 앞서 스택에서 살펴본 것과 비슷한 결론을 얻는다.
- 덱은 양쪽 끝에서 원소를 추가하거나 삭제할 수 있어 일반 큐보다 자유롭게 사용할 수 있다.

### 2. &nbsp; Q & A

**Q**: 브라우저의 앞으로 가기와 뒤로 가기는 이중 연결 리스트로 구현하는가?

브라우저의 앞으로 가기와 뒤로 가기에는 스택의 원리가 쓰인다. 사용자가 새 페이지를 방문하면 그 페이지를 스택의 맨 위에 넣고, 뒤로 가기 버튼을 누르면 그 페이지를 맨 위에서 꺼낸다. ‘덱’ 절에서 살펴보았듯이 덱을 사용하면 몇 가지 추가 연산도 쉽게 구현할 수 있다.

**Q**: 스택에서 노드를 꺼낸 뒤 그 노드의 메모리를 해제해야 하는가?

꺼낸 노드를 나중에 다시 사용할 예정이라면 메모리를 해제할 필요가 없다. 더 이상 사용하지 않는 노드는 `Java`나 `Python` 같은 언어에서 가비지 컬렉터가 메모리를 자동으로 회수하므로 직접 해제할 필요가 없다. `C`와 `C++`에서는 직접 해제해야 한다.

**Q**: 덱은 스택 두 개를 붙여 놓은 것처럼 보이는데, 어디에 쓰이는가?

덱은 스택과 큐를 결합한 것처럼, 또는 스택 두 개를 붙여 놓은 것처럼 볼 수 있다. 스택과 큐의 동작 방식을 모두 지원하므로 두 자료 구조가 쓰이는 모든 곳에 활용할 수 있고 사용 방식도 더 유연하다.

**Q**: 실행 취소(undo)와 다시 실행(redo)은 구체적으로 어떻게 구현하는가?

스택 두 개를 사용한다. 스택 `A`는 실행 취소에, 스택 `B`는 다시 실행에 사용한다.

1. 사용자가 새 작업을 할 때마다 그 작업을 스택 `A`에 넣고 스택 `B`를 비운다.
2. 사용자가 ‘실행 취소’를 하면 스택 `A`에서 가장 최근 작업을 꺼내 스택 `B`에 넣는다.
3. 사용자가 ‘다시 실행’을 하면 스택 `B`에서 가장 최근 작업을 꺼내 스택 `A`에 넣는다.
