11.5   퀵 정렬¶

퀵 정렬(quick sort)은 분할 정복 전략을 이용하는 효율적인 정렬 알고리즘으로 널리 쓰인다.

퀵 정렬의 핵심 연산은 ‘양방향 분할’이다. 배열의 한 원소를 ‘피벗’으로 정하고 이보다 작은 원소는 모두 왼쪽으로, 큰 원소는 모두 오른쪽으로 옮기는 것이 목표다. 구체적인 과정은 아래 그림(11-8)과 같다.

  1. 배열 맨 왼쪽 원소를 피벗으로 고르고 두 포인터 i와 j가 각각 배열의 양 끝을 가리키도록 초기화한다.
  2. 루프를 돌며 매 회전마다 i로 피벗보다 큰 첫 원소를, j로 피벗보다 작은 첫 원소를 찾은 다음 두 원소를 교환한다.
  3. 2.단계를 반복하다가 i와 j가 만나면 멈추고 마지막으로 피벗을 두 부분 배열의 경계로 교환한다.

그림 11-8   양방향 분할 단계

그림 11-8 설명: 2를 피벗으로 한 번의 양방향 분할

오른쪽 포인터 j를 먼저 옮기고 왼쪽 포인터 i를 옮긴다. 잘못된 구간에 있는 원소를 교환한 뒤 마지막에 피벗 2를 경계 위치에 놓는다.

초기 배열은 nums = [2, 4, 1, 0, 3, 5]이고 인덱스는 0~5이다. 현재 구간의 경계는 left = 0, right = 5이며 맨 왼쪽 원소 nums[left] = 2를 피벗으로 선택한다.

왼쪽 포인터 i는 오른쪽으로 가며 피벗보다 큰 첫 원소를 찾고 오른쪽 포인터 j는 왼쪽으로 가며 피벗보다 작은 첫 원소를 찾는다. 이 구현은 매 회전에서 먼저 j를 옮기고 다음에 i를 옮기며, 두 포인터 모두 i < j일 때만 이동한다. 양쪽에서 구간에 맞지 않는 원소를 찾으면 교환한다. 이를 두 포인터가 만날 때까지 반복한 뒤 피벗을 만난 위치로 교환한다.

그림 위에는 배열 nums, 피벗 표시, 구간 경계 포인터 left와 right, 탐색 포인터 i와 j가 있다. 아래에는 partition 함수의 코드가 있고 현재 단계에서 실행하는 문장을 회색으로 강조한다. 마지막에 경계 위치로 교환하기 전까지 피벗 2는 계속 인덱스 0에 있으며 i가 오른쪽으로 이동해도 따라가지 않는다. 분할 경계 left = 0과 right = 5도 내내 그대로이며 마지막 장면에서 포인터 글자만 숨긴다.

  1. 경계, 피벗, 두 포인터 초기화

    초기 배열은 nums = [2, 4, 1, 0, 3, 5]이다. 인덱스 0의 2를 피벗으로 선택한다. 회색으로 강조된 i, j = left, right에 따라 i = 0, j = 5가 되어 각각 2와 5를 가리킨다. 아직 탐색이나 교환은 시작하지 않았다.

  2. 포인터 j가 왼쪽으로 이동해 피벗보다 작은 0 발견

    먼저 j를 옮긴다. 인덱스 5의 5와 인덱스 4의 3은 모두 피벗 2 이상이므로 차례로 건너뛴다. 인덱스 3에서는 0 < 2이므로 멈춘다. 현재 nums = [2, 4, 1, 0, 3, 5]이고 i = 0, j = 3이다. 피벗 2는 여전히 인덱스 0에 있다.

  3. 포인터 i가 오른쪽으로 이동해 피벗보다 큰 4 발견

    이어서 i를 옮긴다. 인덱스 0의 2는 피벗 2보다 크지 않아 오른쪽으로 건너뛴다. 인덱스 1에서는 4 > 2이므로 멈춘다. 현재 nums = [2, 4, 1, 0, 3, 5]이고 i = 1은 4를, j = 3은 0을 가리켜 두 원소를 교환할 준비가 되었다. 피벗 2는 여전히 인덱스 0에 있다.

  4. 4와 0 교환

    인덱스 1의 4와 인덱스 3의 0을 교환해 피벗보다 작은 0을 왼쪽에, 피벗보다 큰 4를 오른쪽에 놓는다. 현재 nums = [2, 0, 1, 4, 3, 5]이고 i = 1, j = 3이다. 피벗 2는 여전히 인덱스 0에 있다.

  5. 포인터 j가 계속 왼쪽으로 이동해 피벗보다 작은 1 발견

    다음 회전에서도 j를 먼저 옮긴다. 인덱스 3의 4 ≥ 2이므로 왼쪽 인덱스 2로 가서 1 < 2를 만나 멈춘다. 현재 nums = [2, 0, 1, 4, 3, 5]이고 i = 1은 0을, j = 2는 1을 가리킨다. 피벗 2는 여전히 인덱스 0에 있다.

  6. 포인터 i가 오른쪽으로 이동해 j와 만남

    인덱스 1의 0 ≤ 2이므로 i가 오른쪽 인덱스 2로 이동해 j와 만난다. 현재 nums = [2, 0, 1, 4, 3, 5]이고 i = j = 2이다. 만난 곳의 값은 1이고 피벗 2는 여전히 인덱스 0에 있다. i의 안쪽 탐색이 멈춘 이유는 피벗보다 큰 원소를 찾아서가 아니라 i < j가 더 이상 성립하지 않아서다.

  7. 만난 위치에서 자기 자신과 교환해도 배열은 그대로

    이번 회전 끝의 nums[i], nums[j] 교환문을 실행한다. i = j = 2이므로 인덱스 2의 1을 자기 자신과 교환한다. nums는 여전히 [2, 0, 1, 4, 3, 5]이고 피벗 2는 인덱스 0에 있다. 이후 i < j가 성립하지 않아 바깥 분할 루프를 종료한다.

  8. 교환을 통해 피벗 2를 경계 인덱스 2에 배치

    루프 뒤에서 피벗을 제자리에 놓는 문장을 실행한다. 인덱스 0의 피벗 2와 인덱스 2의 1을 교환한다. 현재 nums = [1, 0, 2, 4, 3, 5]이고 i = j = 2이며 피벗 2는 최종 인덱스 2에 있다.

  9. 한 번의 분할 완료, 양쪽 부분 배열은 부분 문제로 남음

    return i로 인덱스 2를 반환한다. 현재 nums = [1, 0, 2, 4, 3, 5]이다. 그림에서는 left, right, i, j를 숨기고 중괄호로 왼쪽 부분 배열 [1, 0](인덱스 0~1)과 오른쪽 부분 배열 [4, 3, 5](인덱스 3~5)를 표시한다. 왼쪽 값은 모두 2 이하, 오른쪽 값은 모두 2 이상이지만 양쪽 내부는 아직 정렬되지 않았다.

한 번의 분할로는 피벗의 최종 위치만 확정된다. 양쪽 구간은 각각 재귀적으로 정렬해야 한다.

분할이 끝나면 원래 배열은 왼쪽 부분 배열, 피벗, 오른쪽 부분 배열로 나뉜다. 이때 ‘왼쪽의 임의의 원소 \(\leq\) 피벗 \(\leq\) 오른쪽의 임의의 원소’가 성립한다. 이제 두 부분 배열만 정렬하면 된다.

퀵 정렬의 분할 정복 전략

양방향 분할은 긴 배열 하나를 정렬하는 문제를 더 짧은 두 배열을 정렬하는 문제로 단순화한다.

quick_sort.py
def partition(self, nums: list[int], left: int, right: int) -> int:
    """양방향 포인터로 분할"""
    # nums[left]를 피벗으로 선택
    i, j = left, right
    while i < j:
        while i < j and nums[j] >= nums[left]:
            j -= 1  # 오른쪽에서 왼쪽으로 피벗보다 작은 첫 원소 찾기
        while i < j and nums[i] <= nums[left]:
            i += 1  # 왼쪽에서 오른쪽으로 피벗보다 큰 첫 원소 찾기
        # 원소 교환
        nums[i], nums[j] = nums[j], nums[i]
    # 교환을 통해 피벗을 두 부분 배열의 경계에 배치
    nums[i], nums[left] = nums[left], nums[i]
    return i  # 피벗의 인덱스 반환
quick_sort.cpp
/* 양방향 포인터로 분할 */
int partition(vector<int> &nums, int left, int right) {
    // nums[left]를 피벗으로 선택
    int i = left, j = right;
    while (i < j) {
        while (i < j && nums[j] >= nums[left])
            j--;                // 오른쪽에서 왼쪽으로 피벗보다 작은 첫 원소 찾기
        while (i < j && nums[i] <= nums[left])
            i++;                // 왼쪽에서 오른쪽으로 피벗보다 큰 첫 원소 찾기
        swap(nums[i], nums[j]); // 두 원소 교환
    }
    swap(nums[i], nums[left]);  // 교환을 통해 피벗을 두 부분 배열의 경계에 배치
    return i;                   // 피벗의 인덱스 반환
}

void swap(int[] nums, int i, int j) {
    int tmp = nums[i];
    nums[i] = nums[j];
    nums[j] = tmp;
}

/* 양방향 포인터로 분할 */
func (q *quickSort) partition(nums []int, left, right int) int {
    // nums[left]를 피벗으로 선택
    i, j := left, right

11.5.1   알고리즘의 동작 과정¶

퀵 정렬의 전체 과정은 아래 그림(11-9)과 같다.

  1. 먼저 원래 배열을 한 번 양방향으로 분할하여 아직 정렬되지 않은 왼쪽과 오른쪽 부분 배열을 얻는다.
  2. 그런 다음 두 부분 배열에 각각 양방향 분할을 재귀적으로 적용한다.
  3. 재귀를 계속하다 부분 배열의 길이가 1이 되면 멈춘다. 이로써 전체 배열의 정렬이 끝난다.

그림 11-9   퀵 정렬 과정

그림 11-9 설명: 퀵 정렬의 재귀 과정 개요

양방향 분할마다 먼저 피벗을 최종 위치에 고정한다. 이어서 양쪽 부분 배열을 재귀적으로 분할하다가 부분 구간의 길이가 1 이하가 되면 멈춘다.

입력 배열은 [2, 4, 1, 0, 3, 5]이며 인덱스는 0~5이다. 분할할 때마다 현재 부분 배열의 맨 왼쪽 원소를 피벗으로 선택한다. 재배치하면 피벗 왼쪽의 원소는 모두 피벗 이하, 오른쪽의 원소는 모두 피벗 이상이 되어 피벗이 최종 정렬 위치에 놓인다.

파란 칸은 제자리를 찾은 피벗이고 아래쪽 화살표는 분할된 부분 구간을 가리킨다. 같은 층의 부분 문제를 나란히 그린 것은 재귀의 층과 의존 관계를 나타낼 뿐 병렬 실행을 뜻하지 않는다. 이 절의 코드는 왼쪽 구간을 먼저 재귀 호출한 뒤 오른쪽 구간을 호출한다. 개요에서는 분할 전후의 결과만 보여 주며 두 포인터의 이동과 개별 교환은 생략한다.

아래 표는 길이가 1보다 큰 구간에서 수행한 세 번의 분할을 보여 준다. 분할할 구간과 피벗의 최종 인덱스는 전체 배열 기준이다. 입력 부분 배열과 분할 결과 열에는 원솟값을 표시한다.

코드의 재귀 경계에 따르면 피벗 1이 인덱스 1에 고정된 후 그 오른쪽에 빈 구간 [2, 1]이 생기며 호출은 즉시 끝난다. 그림에는 나머지 단일 원소 구간 세 개만 나온다.

길이가 1보다 큰 구간의 분할
분할할 구간입력 부분 배열피벗값분할 결과피벗의 최종 인덱스
인덱스 0~5[2,4,1,0,3,5]2[1,0,2,4,3,5]2
인덱스 0~1[1,0]1[0,1]1
인덱스 3~5[4,3,5]4[3,4,5]4

세 번 분할한 뒤 피벗 1, 2, 4는 각각 인덱스 1, 2, 4에 고정된다. 인덱스 0, 3, 5의 단일 원소 구간은 바로 종료되어 전체 배열은 [0, 1, 2, 3, 4, 5]가 된다. 길이가 1 이하이면 재귀를 끝내며 따로 병합할 필요가 없다.

    quick_sort(nums, left, pivot - 1)
    quick_sort(nums, pivot + 1, right)
  end
  nums

11.5.2   알고리즘의 특성¶

  • 시간 복잡도 \(O(n \log n)\), 비적응형 정렬: 평균적으로 양방향 분할의 재귀 층수는 \(\log n\)이고 층별 총 반복 횟수는 \(n\)이므로 전체에 \(O(n \log n)\)의 시간이 걸린다. 최악의 경우 매번 길이 \(n\)인 배열을 길이 \(0\)과 \(n - 1\)인 두 부분 배열로 나눈다. 재귀 층수가 \(n\)에 이르고 층별 반복 횟수는 \(n\)이어서 총 \(O(n^2)\)의 시간이 걸린다.
  • 공간 복잡도 \(O(n)\), 제자리 정렬: 입력 배열이 완전히 역순이면 최악의 재귀 깊이 \(n\)에 이르러 스택 프레임 공간을 \(O(n)\)만큼 사용한다. 정렬은 원래 배열에서 이루어지며 추가 배열은 사용하지 않는다.
  • 불안정 정렬: 양방향 분할의 마지막 단계에서 피벗이 값이 같은 원소의 오른쪽으로 옮겨질 수 있다.

11.5.3   퀵 정렬이 빠른 이유¶

이름에서 짐작할 수 있듯이 퀵 정렬에는 효율 면에서 장점이 있다. 평균 시간 복잡도는 병합 정렬 및 힙 정렬과 같지만 일반적으로 퀵 정렬이 더 효율적이다. 주된 이유는 다음과 같다.

  • 최악의 경우가 발생할 확률이 매우 낮다. 퀵 정렬의 최악 시간 복잡도는 \(O(n^2)\)이므로 실행 시간이 병합 정렬만큼 일정하지는 않지만 대다수의 경우 \(O(n \log n)\)의 시간 복잡도로 실행된다.
  • 캐시를 효율적으로 사용한다. 양방향 분할을 실행할 때 시스템이 부분 배열 전체를 캐시에 불러올 수 있어 원소에 효율적으로 접근한다. 힙 정렬처럼 원소 사이를 건너뛰며 접근하는 알고리즘에는 이런 특성이 없다.
  • 시간 복잡도의 상수 계수가 작다. 위 세 알고리즘 중 퀵 정렬이 비교, 대입, 교환 등 전체 연산 수가 가장 적다. 삽입 정렬이 버블 정렬보다 빠른 이유와 비슷하다.

11.5.4   피벗 선택 최적화¶

일부 입력에서 퀵 정렬의 시간 효율이 떨어질 수 있다. 극단적인 예로 입력 배열이 완전히 역순이라고 하자. 맨 왼쪽 원소를 피벗으로 고르면 분할 후 피벗이 오른쪽 끝으로 옮겨져 왼쪽 부분 배열의 길이는 \(n - 1\), 오른쪽 길이는 \(0\)이 된다. 이대로 재귀 호출하면 매번 한쪽의 길이가 \(0\)이 되어 분할 정복의 효과가 사라지고 퀵 정렬은 버블 정렬과 비슷한 형태로 퇴화한다.

이런 상황을 최대한 피하려면 양방향 분할의 피벗 선택 전략을 개선할 수 있다. 예를 들어 원소 하나를 무작위로 골라 피벗으로 쓸 수 있다. 그래도 운이 나빠 매번 좋지 않은 피벗을 고르면 효율은 여전히 떨어진다.

프로그래밍 언어가 일반적으로 생성하는 것은 ‘의사 난수’라는 점에 주의하자. 의사 난수열에 맞추어 특정 테스트 사례를 만들면 퀵 정렬의 효율이 여전히 떨어질 수 있다.

한 걸음 더 나아가 배열에서 후보 원소 세 개(보통 처음, 끝, 중간 원소)를 고른 뒤 세 값의 중앙값을 피벗으로 사용할 수 있다. 그러면 피벗이 너무 작지도 크지도 않을 확률이 크게 높아진다. 후보를 더 많이 선택해 알고리즘이 다양한 입력에서도 잘 작동하도록 할 수도 있다. 이 방식을 쓰면 시간 복잡도가 \(O(n^2)\)까지 나빠질 확률이 크게 낮아진다.

def median_three(self, nums: list[int], left: int, mid: int, right: int) -> int:
    """세 후보 원소의 중앙값 선택"""
    l, m, r = nums[left], nums[mid], nums[right]
    if (l <= m <= r) or (r <= m <= l):
        return mid  # m이 l과 r 사이에 있음
    if (m <= l <= r) or (r <= l <= m):
        return left  # l이 m과 r 사이에 있음
    return right

def partition(self, nums: list[int], left: int, right: int) -> int:
    """양방향 포인터로 분할(세 값의 중앙값 선택)"""
    # nums[left]를 피벗으로 선택
    med = self.median_three(nums, left, (left + right) // 2, right)
    # 교환을 통해 중앙값을 배열의 왼쪽 끝에 배치
    nums[left], nums[med] = nums[med], nums[left]
    # nums[left]를 피벗으로 선택
    i, j = left, right
    while i < j:
        while i < j and nums[j] >= nums[left]:
            j -= 1  # 오른쪽에서 왼쪽으로 피벗보다 작은 첫 원소 찾기
        while i < j and nums[i] <= nums[left]:
            i += 1  # 왼쪽에서 오른쪽으로 피벗보다 큰 첫 원소 찾기
        # 원소 교환
        nums[i], nums[j] = nums[j], nums[i]
    # 교환을 통해 피벗을 두 부분 배열의 경계에 배치
    nums[i], nums[left] = nums[left], nums[i]
    return i  # 피벗의 인덱스 반환

11.5.5   재귀 깊이 최적화¶

일부 입력에서 퀵 정렬은 공간을 많이 사용할 수 있다. 완전히 정렬된 입력 배열을 예로 들자. 재귀 호출에서 부분 배열의 길이가 \(m\)이면 매번 분할할 때 길이 \(0\)인 왼쪽 부분 배열과 길이 \(m - 1\)인 오른쪽 부분 배열이 생긴다. 재귀 호출 한 층마다 문제의 크기가 원소 하나만큼만 줄어 재귀 트리 높이가 \(n - 1\)에 이른다. 이때 스택 프레임 공간이 \(O(n)\)만큼 필요하다.

스택 프레임이 계속 쌓이는 것을 막으려면 매번 양방향 분할 뒤 두 부분 배열의 길이를 비교해 더 짧은 쪽만 재귀 호출한다. 짧은 쪽의 길이는 \(n / 2\)를 넘지 않으므로 재귀 깊이는 \(\log n\) 이하가 되고 최악의 공간 복잡도는 \(O(\log n)\)으로 개선된다. 코드는 다음과 같다.

def quick_sort(self, nums: list[int], left: int, right: int):
    """퀵 정렬(재귀 깊이 최적화)"""
    # 부분 배열의 길이가 1이면 종료

        # 양방향 포인터로 분할
        pivot = self.partition(nums, left, right)

            right = pivot - 1  # 남은 미정렬 구간은 [left, pivot - 1]

      quick_sort(nums, left, pivot - 1)
      left = pivot + 1 # 남은 미정렬 구간은 [pivot + 1, right]
    else
      quick_sort(nums, pivot + 1, right)
      right = pivot - 1 # 남은 미정렬 구간은 [left, pivot - 1]
    end
  end
end
