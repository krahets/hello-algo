# 雜湊表求兩數之和

走訪 nums = \[2, 7, 11, 15\]，依次將 2:0、7:1 存入雜湊表 map；訪問 11 時查到補數 2 已在表中，直接返回 \[0, 2\]。

## 問題與輸入

給定整數陣列 nums = \[2, 7, 11, 15\]（索引從 0 到 3）與目標和 target = 13。

藉助輔助雜湊表 map 記錄已走訪過的元素：鍵（key，標有“元素”）存陣列元素值，值（value，標有“索引”）存該元素對應的陣列索引。單層迴圈每輪先查詢補數 target − nums\[i\] 是否已在 map 中：若存在則立即返回 \[map\[target − nums\[i\]\], i\]；若不存在才將當前鍵值對 nums\[i\]: i 寫入 map。

## 結構與關係

每輪“先查補數、後存當前元素”的順序保證了配對的另一個元素必定來自當前位置 i 之前的不同索引。三幅分步畫面依次展示 i = 0、1、2 時的判斷與雜湊表狀態（注意第 1 步畫面展示的是完成首次插入 2 → 0 之後的狀態，而非空表）。

## 第 1 步：未找到補數 11，記錄 2

指標 i = 0 指向元素 2，圖右側說明“∵ 13 – 2 = 11 不在 map 中 ∴ 將元素 2 新增進 map”。此時初始為空的雜湊表寫入首條鍵值對 key = 2、value = 0。

## 第 2 步：未找到補數 6，記錄 7

指標 i = 1 指向元素 7，圖右側說明“∵ 13 – 7 = 6 不在 map 中 ∴ 將元素 7 新增進 map”。雜湊表中此前僅有鍵 2 而無鍵 6，因此繼續寫入鍵值對 key = 7、value = 1。

## 第 3 步：找到補數 2，返回索引

指標 i = 2 指向元素 11，圖右側說明“∵ 13 – 11 = 2 在 map 中 ∴ 返回元素組合索引 \[0, 2\]”。雜湊表中鍵 2 對應的索引 value 為 0，與當前索引 i = 2 組成答案 \[0, 2\] 直接返回，不再將 11 寫入表中。

<details><summary>本步完整狀態</summary><p>陣列 nums=[2,7,11,15]，索引從 0 到 3，目標和 target=13。i=2，當前值 11；補數 2 已存在，map[2]=0；返回 [0,2]。map 仍為 {2:0,7:1}，未加入 11，15 尚未處理且不再需要處理。</p></details>

## 結果

當 i = 2 訪問元素 11 時，補數 13 − 11 = 2 在 map 中命中舊索引 0，立即返回 \[0, 2\]；當前元素 11 無須再存入 map，末尾索引 3 的 15 也無須繼續走訪。在雜湊查詢平均為 O(1) 的前提下，雜湊最佳化將平均時間複雜度從 O(n²) 降至 O(n)，輔助空間複雜度為 O(n)，體現了“以空間換時間”的策略。
