# 小結

### 重點回顧

- 動態規劃將原問題分解成子問題，儲存子問題的解來避免重複計算，提高運算效率。
- 若不考慮耗時，所有動態規劃問題都可用回溯法（暴力搜尋）求解，但遞迴樹中有大量重疊子問題，效率很低。加入記憶表，儲存所有算過的子問題的解，就能讓每個重疊子問題都只計算一次。
- 記憶化搜尋是由上而下的遞迴解法，對應的動態規劃則是由下而上逐步推算，就像填表一樣。由於目前狀態只依賴附近的某些狀態，因此可以減少 $dp$ 表的一個維度，降低空間複雜度。
- 分解子問題是通用的演算法設計思路，在分治法、動態規劃與回溯法中各有不同的特性。
- 動態規劃問題有三大特性：重疊子問題、最佳子結構與無後效性。
- 若能用子問題的最佳解構成原問題的最佳解，這個問題就具有最佳子結構。
- 無後效性指的是，狀態未來的發展只取決於目前狀態，與先前經歷過的所有狀態無關。許多組合最佳化問題不符合無後效性，無法用動態規劃快速求解。

**背包問題**

- 背包問題是最典型的動態規劃問題之一，有 0-1 背包、完全背包、多重背包等變形。
- 0-1 背包的狀態記錄從前 $i$ 件物品中選擇，在背包容量為 $c$ 時可取得的最大價值。比較不放入與放入物品的兩種選擇，就能找出最佳子結構，建立狀態轉移方程式。做空間最佳化時，由於每個狀態依賴正上方與左上方的狀態，必須反向走訪串列，避免左上方的狀態被覆寫。
- 完全背包問題中，每種物品的選取數量不限，所以選擇放入物品時的狀態轉移與 0-1 背包不同。由於狀態依賴正上方與正左方的狀態，做空間最佳化時應正向走訪。
- 零錢兌換是完全背包問題的變形。目標從求「最大」價值變成求「最少」硬幣數，因此要將狀態轉移方程式中的 $\max()$ 改為 $\min()$。由於目標也從「不超過」背包容量變成「剛好」湊出目標金額，因此用 $amt + 1$ 表示「無法湊出目標金額」的無效解。
- 零錢兌換問題 II 將目標從「最少硬幣數」改成「硬幣組合數」，狀態轉移方程式也隨之將 $\min()$ 改成加法。

**編輯距離問題**

- 編輯距離（Levenshtein 距離）用來衡量兩個字串的相似程度，定義為從一個字串轉成另一個字串所需的最少編輯步數，可用的操作有插入、刪除與取代。
- 編輯距離問題的狀態記錄將 $s$ 的前 $i$ 個字元轉成 $t$ 的前 $j$ 個字元所需的最少編輯步數。當 $s[i-1] \ne t[j-1]$ 時，有插入、刪除與取代三種選擇，各自對應一個剩餘的子問題。據此可以找出最佳子結構並建立狀態轉移方程式。當 $s[i-1] = t[j-1]$ 時，則無須編輯目前的字元。
- 在編輯距離問題中，每個狀態依賴正上方、正左方與左上方的狀態。壓縮空間後，直接正向或反向走訪都無法正確進行狀態轉移。我們可用一個變數暫存左上方的狀態，將情況化為與完全背包問題相同，再正向走訪。
