# 用十六位形式展示 Hello演算法 的碼點

將“Hello演算法”七個字元統一寫成 16 位（2 位元組）二進位制碼點：五個英文字元在高 8 位補 0，“算”和“法”兩個漢字的碼點也寫為 16 位。

## 問題與輸入

畫面包含“字元”和“Unicode”兩列，自上而下依次排列無空格的七個字元“Hello演算法”，展示如何透過高位補 0 將本例的英文與中文碼點表示對齊為統一的 2 位元組（16 位）等長編碼。

## 結構與關係

前五行是英文字元 H、e、l、l、o，右側大括號標註“長度為 1 位元組的英文字元 (高位填 0)”：每個字元的高 8 位均以灰色斜體寫出 00000000，低 8 位以彩色粗體寫出各自的 ASCII 碼點——H 為 00000000 01001000，e 為 00000000 01100101，第 3 行和第 4 行的兩個 l 均為 00000000 01101100，o 為 00000000 01101111。

後兩行是中文字元“算”和“法”，右側大括號標註“長度為 2 位元組的中文字元”，高 8 位與低 8 位均為有效碼點位：“算”對應 01111011 10010111（十六進位制 U+7B97），“法”對應 01101100 11010101（十六進位制 U+6CD5）。

Unicode 為每個字元分配唯一碼點，若直接將 1 位元組的英文碼點與 2 位元組的中文碼點緊挨儲存，解析器將無法判斷連續的 2 個位元組究竟代表 1 個漢字還是 2 個英文字母。本圖展示的定長方案為所有 1 位元組英文字元統一補上一整個全 0 的高位元組（00000000），使七個字元全部對齊為 16 位；注意這只是針對本例基本多語言平面（BMP）內字元的 16 位等長示意，完整 Unicode 字元集的碼點最高可達 21 位（U+10FFFF），並非所有 Unicode 字元都固定為 2 位元組。

## 結果

對於本圖“Hello演算法”這七個 BMP 字元，若採用圖示的 16 位等長儲存方式，系統可每隔 2 位元組切分出一個字元，代價是五個英文字母的儲存空間比 ASCII 翻了一倍。這只是本例的儲存示意；Unicode 定義碼點，實際佔用位元組數取決於 UTF-8、UTF-16 等編碼，不能概括為所有 Unicode 字元都固定佔 2 位元組。
