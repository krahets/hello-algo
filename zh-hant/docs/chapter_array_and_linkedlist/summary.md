# 4.5 &nbsp; 小結

### 1. &nbsp; 重點回顧

- 陣列和鏈結串列是兩種基本的資料結構，分別代表資料在電腦記憶體中的兩種儲存方式：連續空間儲存和分散空間儲存。兩者的特性互補。
- 陣列支援隨機存取，元素占用的記憶體較少，但插入與刪除元素的效率較低，且初始化後長度固定。
- 鏈結串列只需修改參照（指標），就能有效率地插入或刪除節點，長度也能彈性調整。缺點是存取節點的效率較低，且占用較多記憶體。常見類型有單向、環狀和雙向鏈結串列。
- 列表是一組有順序的元素，支援新增、刪除、查詢及修改，通常以動態陣列實作。它保留陣列的優點，也能彈性調整長度。
- 列表讓陣列實用許多，但也可能浪費部分記憶體空間。
- 程式執行期間，資料主要存放在記憶體中。陣列使用記憶體空間的效率較高，鏈結串列則更有彈性。
- 快取在載入資料時，透過快取列、預取機制，以及空間區域性和時間區域性等特性，讓 CPU 能快速存取資料，大幅提高程式執行效率。
- 陣列的快取命中率較高，因此通常比鏈結串列更有效率。選擇資料結構時，仍應依具體的需求和情境做決定。

### 2. &nbsp; Q & A

**Q**：陣列放在堆疊或堆積上，會影響時間與空間效率嗎？

無論放在堆疊或堆積上，陣列都占用連續的記憶體，操作資料的效率大致相同。不過，堆疊和堆積各有特性，因此有以下差異。

1. 配置與釋放效率：堆疊是一塊較小的記憶體，由編譯器自動安排配置。堆積的空間較大，可以在程式碼中動態配置，也較容易產生碎片。因此，堆積上的配置與釋放操作通常比堆疊上的慢。
2. 大小限制：堆疊的空間較小，堆積的大小通常取決於可用記憶體，因此堆積較適合儲存大型陣列。
3. 彈性：堆疊上的陣列需要在編譯時確定大小，堆積上的陣列則可在執行時動態決定大小。

**Q**：為什麼陣列要求元素的型別相同，介紹鏈結串列時卻沒有強調這個要求？

鏈結串列由節點組成，節點之間以參照（指標）相連，各節點可以儲存不同型別的資料，例如 `int`、`double`、`string`、`object` 等。

陣列的元素則必須具備相同型別，才能藉由計算位移量找到對應的元素。例如，假設陣列同時包含 `int` 和 `long` 兩種型別的元素，每個元素分別占 4 位元組或 8 位元組，就無法使用以下公式計算位移量，因為陣列中有兩種不同的「元素長度」。

```shell
# 元素的記憶體位址 = 陣列的記憶體位址（第一個元素的位址） + 元素長度 * 元素索引
```

**Q**：刪除節點 `P` 後，需要將 `P.next` 設為 `None` 嗎？

可以保留 `P.next` 的原值。就這條鏈結串列而言，從頭節點走訪到尾節點都不會再遇到 `P`，這表示節點 `P` 已從串列中刪除。此時節點 `P` 指向何處，都不會影響這條串列。

單就資料結構與演算法的解題而言，只要程式邏輯正確，保留連結並無妨。在實作標準函式庫時，斷開連結更安全，邏輯也更清楚。若保留連結，而被刪除的節點未正常回收，後繼節點的記憶體回收也會受到影響。

**Q**：在鏈結串列中插入或刪除節點的時間複雜度為 $O(1)$，但在這之前需要花 $O(n)$ 的時間尋找元素。為什麼時間複雜度不是 $O(n)$？

若要先尋找元素再刪除，時間複雜度確實是 $O(n)$。不過，鏈結串列能在 $O(1)$ 時間內插入和刪除節點，在其他應用上很有優勢。例如，雙端佇列適合用鏈結串列實作，只要維護分別指向頭、尾節點的指標，每次插入或刪除的時間複雜度都是 $O(1)$。

**Q**：在「鏈結串列的定義與儲存方式」圖中，淺藍色的節點指標是獨占一個記憶體位址，還是和節點值各占一半？

這張圖只表示概念。若要知道實際占用的空間，需要依具體情況分析。

- 節點值的型別不同，占用的空間也不同，例如 `int`、`long`、`double` 和類別的實例物件等。
- 指標變數占用多少記憶體，取決於作業系統和編譯環境，多半是 8 位元組或 4 位元組。

**Q**：在列表尾端加入元素的時間複雜度一定都是 $O(1)$ 嗎？

加入元素時，若原本的列表已放不下，就得先擴充容量。系統會配置一塊新的記憶體，將原列表的所有元素搬過去，這時時間複雜度就是 $O(n)$。

**Q**：「列表讓陣列實用許多，但也可能浪費部分記憶體空間。」這裡浪費的空間，是指容量、長度、擴充倍數等額外變數占用的記憶體嗎？

這裡的空間浪費主要來自兩方面。首先，列表會設定初始長度，但我們不一定用得到這麼多空間。其次，為了避免頻繁擴充容量，通常會將容量乘上一個係數，例如 $\times 1.5$。如此一來也會出現許多空位，而我們通常不會全部用完。

**Q**：在 Python 中，初始化 `n = [1, 2, 3]` 後，這 3 個元素的位址彼此相連；但初始化 `m = [2, 1, 3]` 後，各元素的 id 並不連續，反而分別與 `n` 中對應元素的 id 相同。既然元素的位址不連續，`m` 還算是陣列嗎？

若將列表中的元素換成鏈結串列節點 `n = [n1, n2, n3, n4, n5]`，這 5 個節點物件通常也會分散在記憶體各處。但只要給定列表索引，我們仍能在 $O(1)$ 時間內取得節點的記憶體位址，存取對應的節點。這是因為陣列儲存的是節點的參照，而非節點本身。

與許多語言不同，Python 的數字也包裝成物件，列表儲存的是數字物件的參照。因此，兩個陣列裡相同的數字會有相同的 id，而這些數字的記憶體位址不必連續。

**Q**：C++ STL 的 `std::list` 已經實作了雙向鏈結串列，但有些演算法書籍似乎很少直接使用它。這是因為它有什麼限制嗎？

一方面，我們通常偏好用陣列實作演算法，只在必要時使用鏈結串列，主要有兩個原因。

- 空間成本：每個元素都需要額外儲存兩個指標，分別指向前一個與後一個元素，因此 `std::list` 通常比 `std::vector` 占用更多空間。
- 快取使用效率低：由於資料並非連續存放，`std::list` 使用快取的效率較低。一般而言，`std::vector` 的效能較佳。

另一方面，需要使用鏈結串列的情況主要是二元樹和圖。堆疊和佇列則通常使用程式語言提供的 `stack` 和 `queue`，而非鏈結串列。

**Q**：用 `res = [[0]] * n` 產生的二維列表中，每個 `[0]` 都是獨立的嗎？

它們並不獨立。這個二維列表中的所有 `[0]` 其實都指向同一個物件。修改其中一個元素時，其他對應位置的元素也會跟著改變。

若希望二維列表中的每個 `[0]` 都是獨立的，可以寫成 `res = [[0] for _ in range(n)]`。這種寫法會初始化 $n$ 個彼此獨立的 `[0]` 列表物件。

**Q**：用 `res = [0] * n` 產生的列表中，每個整數 0 都是獨立的嗎？

在這個列表中，所有整數 0 都指向同一個物件。這是因為 Python 會將小整數（通常是 -5 到 256）放入快取，盡可能重複使用這些物件，以提升效能。

雖然各個元素都指向同一個物件，但我們仍能分別修改列表中的每個元素，因為 Python 的整數是「不可變物件」。修改某個元素，其實是讓它改為參照另一個物件，原本的物件本身不會改變。

然而，若列表元素指向「可變物件」（例如列表、字典或類別的實例），透過其中一個元素修改物件內容，便會直接改變物件本身。此時透過其他參照同一物件的元素，也會看到相同的變化。
