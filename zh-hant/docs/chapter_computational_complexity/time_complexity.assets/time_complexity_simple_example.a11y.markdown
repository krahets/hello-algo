# 演算法 A、B 和 C：時間長短與增長趨勢

演算法 A 與 C 的列印次數固定不變，同屬常數階 O(1)；演算法 B 的列印次數隨輸入規模 n 線性增長，屬線性階 O(n)。

## 問題與輸入

設輸入資料大小為 n，三個演算法執行同一種列印操作：演算法 A 只打印 1 次，演算法 B 迴圈列印 n 次，演算法 C 迴圈列印 1000000 次。

座標圖橫軸表示輸入資料大小 n，標有刻度 0 至 9；縱軸表示演算法執行時間，自下而上可見刻度為 0、5、10、豎向省略號與 1000000。

## 結構與關係

圖中用三條不同顏色的線條對比執行時間的變化走勢：綠色直線“演算法 A — 常數階”緊貼橫軸上方（位於刻度 0 與 5 之間，對應 1 次操作），橙色直線“演算法 C — 常數階”位於縱軸高處的刻度 1000000，兩條水平線的高度都不隨 n 增大而改變。

藍色斜線“演算法 B — 線性階”從橫軸 0 處的高度 0 出發，在 n = 1 處與綠色 A 線相交，隨後隨 n 增大向右上方均勻上升，在 n = 9 處升至刻度 10 附近。由於縱軸在刻度 10 與 1000000 之間用省略號壓縮了巨大跨度，不能直接按畫面上的垂直距離測算真即時間比例。

演算法 A（1 次列印）與演算法 C（1000000 次列印）耗時相差極大，但兩者的操作數量都與輸入規模 n 無關，增長趨勢相同，因此時間複雜度均為常數階 O(1)。演算法 B 的列印次數與 n 成正比，時間複雜度為線性階 O(n)：在圖中 n = 0 至 9 的小規模區間內，B 的耗時遠低於 C；但當 n 超過 1000000 時，B 的操作數量就會反超 C。

## 結果

時間複雜度衡量的是執行時間隨資料規模 n 增大的漸近增長趨勢，而非固定輸入下的實際耗時。在本例同一種列印操作的計數模型下，當 n 超過 1000000，B 的操作次數就會超過 A 和 C；但同為常數階 O(1) 的演算法 A 和演算法 C，實際執行時間仍可能相差懸殊。
