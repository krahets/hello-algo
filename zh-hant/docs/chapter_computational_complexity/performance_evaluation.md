# 2.1 &nbsp; 評估演算法效率

設計演算法時，我們依序追求以下兩個目標。

1. **找到解法**：對於規定範圍內的輸入，演算法都必須能可靠地求出正確答案。
2. **尋找最佳解法**：同一個問題可能有多種解法，我們希望找出效率盡可能高的演算法。

也就是說，在能正確解決問題的前提下，效率是衡量演算法優劣的主要指標，包含以下兩個面向。

- **時間效率**：演算法需要多少執行時間。
- **空間效率**：演算法占用多少記憶體空間。

簡單來說，**我們的目標是設計「既快又省」的資料結構與演算法**。要比較不同的演算法，並據此設計與改良演算法，就必須能有效評估它們的效率。

評估效率的方法主要有兩種：實際測試與理論估算。

## 2.1.1 &nbsp; 實際測試

假設演算法 `A` 與 `B` 都能解決同一個問題，要怎麼比較兩者的效率？最直接的方法是找一臺電腦，分別執行兩個演算法，觀察並記錄執行時間與記憶體用量。這種評估方式能反映實際執行情況，但也有明顯的限制。

首先，**測試環境造成的干擾很難排除**。硬體配置會影響演算法的效能。例如，適合平行運算的演算法在多核心 CPU 上更能發揮效能，頻繁存取記憶體的演算法則在配備高效能記憶體的電腦上表現較好。換句話說，同一個演算法在不同電腦上的測試結果可能不同。若要在各式各樣的電腦上逐一測試，再計算平均效率，並不切實際。

其次，**完整測試會耗費大量資源**。輸入資料量不同，演算法的效率也會不同。例如，資料量小時，演算法 `A` 可能比演算法 `B` 執行得快；資料量大時，結果可能剛好相反。要得到有說服力的結論，就得測試各種規模的輸入資料，這需要大量的運算資源。

## 2.1.2 &nbsp; 理論估算

由於實際測試有不少限制，我們也可以透過計算來評估演算法的效率。這種估算方法稱為<u>漸近複雜度分析（asymptotic complexity analysis）</u>，簡稱<u>複雜度分析</u>。

複雜度分析能呈現演算法所需的時間與空間如何受到輸入資料規模的影響。**它描述的是：隨著輸入資料規模增加，演算法所需的時間與空間如何成長**。我們可以從三個重點來理解這個定義。

- 「時間與空間」這兩種資源，分別對應<u>時間複雜度（time complexity）</u>與<u>空間複雜度（space complexity）</u>。
- 「隨著輸入資料規模增加」說明了複雜度反映的是演算法執行效率與輸入資料規模的關係。
- 「時間與空間的成長趨勢」強調，複雜度分析關心的是時間與空間成長得多快，而非執行時間或空間用量的確切數值。

**複雜度分析能克服實際測試的限制**，原因如下。

- 無須實際執行程式碼，較為節能環保。
- 分析與測試環境無關，結果適用於各種執行平台。
- 可以看出不同資料量下的演算法效率，尤其是資料量大時的效能表現。

!!! tip

    如果你還不太熟悉複雜度的概念，不用擔心，後面幾節會詳細介紹。

複雜度分析提供了一把衡量演算法效率的「尺」，讓我們能評估演算法需要多少時間與空間，進而比較不同演算法的效率。

複雜度是數學概念，對初學者而言可能較抽象，學起來也比較吃力。從這個角度來看，複雜度分析似乎不適合放在最前面介紹。不過，討論資料結構與演算法的特性時，很難避開執行速度與空間用量這兩個問題。

因此，建議你在深入學習資料結構與演算法之前，**先初步掌握複雜度分析，學會分析簡單演算法的複雜度**。
