# 6.4 &nbsp; 本章小結

### 1. &nbsp; 重點回顧

- 輸入 `key` 後，雜湊表能在 $O(1)$ 的時間內查到 `value`，效率很高。
- 雜湊表的常用操作包括查詢、新增鍵值對、刪除鍵值對，以及走訪雜湊表。
- 雜湊函式將 `key` 對應到陣列索引，讓我們能存取對應的桶，取得 `value`。
- 兩個不同的 `key` 經過雜湊函式計算後，可能得到相同的陣列索引，導致查詢結果錯誤。這種現象稱為雜湊碰撞。
- 雜湊表的容量越大，發生碰撞的機率就越低，因此可以透過擴充容量來緩解碰撞。和擴充陣列一樣，擴充雜湊表的成本很高。
- 負載因子是雜湊表中的元素數量除以桶數所得的比值。它反映雜湊碰撞的嚴重程度，常用來判斷何時該擴充雜湊表的容量。
- 鏈結法將桶中的單一元素改為鏈結串列，把所有發生碰撞的元素存在同一條串列中。不過，串列太長會降低查詢效率，可以進一步將它改為紅黑樹來提升效率。
- 開放定址法透過多次探測處理雜湊碰撞。線性探測使用固定的步長，缺點是不能直接刪除元素，而且容易產生群聚。多重雜湊則用多個雜湊函式探測，比線性探測更不容易產生群聚，但也增加了計算量。
- 不同程式語言實作雜湊表的方式各有不同。例如，Java 的 `HashMap` 採用鏈結法，Python 的 `dict` 則採用開放定址法。
- 用在雜湊表時，我們希望雜湊演算法具有確定性、效率高，且能讓資料均勻分布。用在密碼學時，還應具備抗碰撞性和雪崩效應。
- 雜湊演算法通常採用大質數作為模數，盡可能讓雜湊值均勻分布，以減少雜湊碰撞。
- 常見的雜湊演算法有 MD5、SHA-1、SHA-2 和 SHA-3 等。MD5 常用來檢查檔案完整性，SHA-2 則常用於安全應用與通訊協定。
- 程式語言通常會為各種資料型別提供內建的雜湊演算法，以便計算雜湊表中的桶索引。通常只有不可變物件可以計算雜湊值。

### 2. &nbsp; Q & A

**問**：在什麼情況下，雜湊表的時間複雜度是 $O(n)$？

雜湊碰撞較為嚴重時，雜湊表的時間複雜度會退化為 $O(n)$。若雜湊函式設計良好、容量適當，且碰撞分布均勻，時間複雜度就是 $O(1)$。使用程式語言內建的雜湊表時，通常視其時間複雜度為 $O(1)$。

**問**：為什麼不用雜湊函式 $f(x) = x$ 呢？這樣就不會有碰撞了。

若採用雜湊函式 $f(x) = x$，每個元素都有唯一對應的桶索引，這就等同於使用陣列。然而，輸入空間通常遠大於輸出空間（陣列長度），因此雜湊函式的最後一步往往是對陣列長度取餘數。換句話說，雜湊表的目標是將較大的狀態空間對應到較小的空間，同時提供 $O(1)$ 的查詢效率。

**問**：雜湊表的底層用到陣列、鏈結串列和二元樹，為什麼效率還能比它們更高？

首先，雜湊表提高了時間效率，卻降低了空間效率。它占用的記憶體中，有相當一部分沒有用到。

其次，雜湊表只有在特定情境下才比較省時。如果用陣列或鏈結串列也能以相同的時間複雜度實作某項功能，通常還會比雜湊表快。這是因為計算雜湊函式需要時間，使時間複雜度中的常數項較大。

最後，雜湊表的時間複雜度可能退化。例如，採用鏈結法時，需要在鏈結串列或紅黑樹中查找，仍有退化為 $O(n)$ 時間的風險。

**問**：多重雜湊也不能直接刪除元素嗎？標記為已刪除的空間還能再用嗎？

多重雜湊是開放定址法的一種。開放定址法都不能直接刪除元素，因此需要使用刪除標記。標記為已刪除的空間仍然可以再利用。插入新元素時，如果透過雜湊函式找到標記為已刪除的位置，就可以將新元素放在那裡。這樣既能維持原本的探測順序，也能確保雜湊表的空間使用率。

**問**：採用線性探測時，為什麼在查找元素的過程中也會遇到雜湊碰撞？

查找時，用雜湊函式找到對應的桶和鍵值對，若發現 `key` 不相符，就表示發生了雜湊碰撞。因此，線性探測會按預先設定的步長依序向後查找，直到找到正確的鍵值對，或確定找不到而結束。

**問**：為什麼擴充雜湊表的容量能緩解碰撞？

雜湊函式的最後一步往往是對陣列長度 $n$ 取模（取餘數），讓輸出值落在陣列索引的範圍內。擴充後，陣列長度 $n$ 改變，`key` 對應的索引也可能改變。原本落在同一個桶的多個 `key`，擴充後可能會分散到不同的桶，因而緩解碰撞。

**問**：如果是為了有效率地存取資料，直接用陣列不就好了嗎？

當資料的 `key` 是連續且範圍不大的整數時，直接使用陣列就很簡單，也很有效率。但當 `key` 是其他型別（例如字串）時，就需要用雜湊函式將 `key` 對應到陣列索引，再透過桶陣列存放元素。這樣的結構就是雜湊表。
