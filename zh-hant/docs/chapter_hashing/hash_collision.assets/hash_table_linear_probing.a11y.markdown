# 開放定址雜湊表：步長為 1 的線性探查

不引入額外鏈結串列，所有鍵值對均直接存放在桶陣列內；發生雜湊衝突時，從起始桶按步長 1 向下線性探查，放入第一個遇到的空桶。

## 問題與輸入

左側說明框標註“開放定址：線性探查，步長為 1”，下方標註“雜湊函式 key % 100；後兩位相同的 key 會發生雜湊衝突”。

右側僅有一個一維桶陣列，每個槽位最多存放一個鍵值對。在“索引”列與“陣列”列之間，圖用兩個左花括號分別將上方的 3 個連續桶括向加粗索引 00，將下方的 5 個連續桶括向加粗索引 76，表示這兩簇元素各自的雜湊起始桶為 00 和 76。

## 結構與關係

第一簇包含後兩位均為 00 的三個鍵 200、500、300：插入 (200, A) 時直接落入起始桶 00；插入 (500, D) 時發現桶 00 已被佔用，便按步長 1 向下探測並存入桶 01；插入 (300, Y) 時依次探測過 00、01，最終存入桶 02。

第二簇包含後兩位均為 76 的五個鍵 076（圖中補零寫為三位）、876、276、676、776：它們全都從起始桶 76 出發向下線性探查，依次落入桶 76、77、78 以及其後緊鄰的兩個桶槽位（圖中 78 下方用省略號“…”代表後續遞增索引，見下表）。

## 起始桶 00 與 76 處的兩組線性探查簇

圖中兩個花括號清晰標出了線性探查的聚集效應：雜湊值為 00 的三個鍵 200、500、300 依次佔據連續槽位 00、01、02；雜湊值為 76 的五個鍵 076、876、276、676、776 依次佔據從 76 開始的五個連續槽位。例如查詢鍵 276 時，先由 276 % 100 = 76 訪問桶 76（存有 076，不匹配），再按步長 1 探測桶 77（存有 876，不匹配），接著探測桶 78 才找到匹配的 (276, E)。

## 結果

在開放定址的線性探查中，元素的實際陣列下標可能排在其雜湊起始桶之後；查詢時同樣必須從 key % 100 對應的起始桶開始，按步長 1 依次向後比對 key。
