# 鏈式位址雜湊表的最佳分佈與最差退化對比

對比六個鍵值對 (k₁, s₁) 至 (k₆, s₆) 在鏈式位址雜湊表中的兩種極端分佈：均勻分散到各桶時查詢時間複雜度為 O(1)，全部衝突集中到單個桶時退化為 O(n)。

## 問題與輸入

畫面左上方總標題為“鏈式位址雜湊表”，上下並列兩個淺綠色面板，分別展示同一批六個鍵值對 (k₁, s₁) 至 (k₆, s₆) 的最佳情況與最差情況。

每個面板左側的淺藍色豎欄表示桶陣列（包含每個非空桶鏈結串列的頭節點及代表其餘桶的省略號“…”），右側透過水平箭頭表示桶內連線的單向鏈結串列節點。

## 結構與關係

上方面板展示“最佳情況：鍵值對平均分佈在各個桶中，時間複雜度 O(1)”。六個鍵值對均勻分散在三個已畫出的桶中：第一個桶連線 (k₁, s₁) → (k₂, s₂)，第二個桶連線 (k₃, s₃) → (k₄, s₄)，第三個桶連線 (k₅, s₅) → (k₆, s₆)。每個桶的鏈結串列長度都很短（僅 2 個節點），定位到桶後只需常數次比較即可完成查詢。當資料規模增長時，O(1) 查詢還需要維持適當的負載因子，使平均鏈長保持常數量級；僅有分佈均勻並不足以無條件保證這一複雜度。

下方面板展示“最差情況：鍵值對全部分佈在單個桶中，時間複雜度 O(n)”。六個鍵值對的雜湊值全部相同，統統落入第一個桶並串成一條長達 6 個節點的單向鏈結串列：(k₁, s₁) → (k₂, s₂) → (k₃, s₃) → (k₄, s₄) → (k₅, s₅) → (k₆, s₆)，而下方其餘桶全空（以省略號表示）。此時雜湊表徹底退化為單向鏈結串列，查詢末尾元素需要走訪全部 n 個節點。

## 六個鍵值對的均勻分佈 O(1) 與單桶退化 O(n)

對比兩圖可見，同樣存放 (k₁, s₁) 到 (k₆, s₆) 六個鍵值對：上圖將它們平均分配到三個桶，每條鏈結串列只有 2 個節點，例如查詢 k₆ 只需在第三個桶內檢查 k₅ 和 k₆ 兩項，查詢時間複雜度為 O(1)；下圖則把六個鍵值對全部擠進第一個桶，查詢 k₆ 必須從 k₁ 一路順著鏈結串列走訪 6 個節點到鏈尾，當資料規模為 n 時時間複雜度退化為 O(n)。

## 結果

雜湊演算法的設計目標正是讓鍵值分佈儘量接近上圖所示的均勻狀態（O(1) 查詢），避免出現下圖所示所有鍵扎堆落入同一桶的 O(n) 退化。
