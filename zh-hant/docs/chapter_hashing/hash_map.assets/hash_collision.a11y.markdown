# 雜湊衝突：兩個不同學號對映到同一個桶索引

當雜湊函式為 key % 100 時，後兩位相同的不同學號 20336 與 12836 都會對映到 36 號桶，引發雜湊衝突並導致未作衝突處理時誤讀結果。

## 問題與輸入

本圖沿用上一圖的容量 100 桶陣列與雜湊函式 key % 100，其中 36 號桶當前存放的是鍵值對 (12836, “小哈”)。

正文以學號 20336 和 12836 說明兩個不同輸入的後兩位均為 36，因此會對映到同一桶；本圖及相關正文沒有給出 20336 對應的真實姓名。

## 結構與關係

左側“輸入 key”列從上到下給出橙色 20336 和藍色 12836。兩條有向曲線經過“雜湊函式 key % 100”後，在進入索引 36 前匯合到一起，圖中在匯合處上方用粉紅色標籤醒目標註“雜湊衝突”。

由於 36 號陣列桶只放了一個鍵值對 (12836, “小哈”)，且此處尚未引入衝突解決機制，橙色路徑（查詢 20336）與藍色路徑（查詢 12836）穿過 36 號桶後，在右側“輸出 value”列雙雙輸出了“小哈”（上方橙色框“小哈”、下方藍色框“小哈”），直觀揭示了直接按雜湊值讀取而不處理衝突會造成資料張冠李戴。

## 20336 與 12836 在 36 號桶發生雜湊衝突

輸入學號 20336 和 12836 對 100 取餘的結果均為 36，兩條路徑同時指向 36 號桶並觸發“雜湊衝突”標註。因為 36 號桶內實際儲存的是 (12836, “小哈”)，若不核對完整學號也不做衝突處理，對 20336 的查詢就會錯誤地讀到屬於 12836 的“小哈”；對 12836 返回“小哈”則與桶內學號匹配。

## 結果

多個不同輸入經雜湊函式得到相同桶索引的現象稱為雜湊衝突；雜湊表可用鏈式位址或開放定址等機制正確區分和儲存衝突鍵，擴容則用於降低負載並緩解衝突。
