# Итоги

### Главное в этой главе

- Двоичный поиск использует упорядоченность данных и на каждой итерации сокращает интервал поиска вдвое. Для него нужны отсортированные данные. Такой поиск подходит только для массивов и структур данных на их основе.
- Полный перебор находит данные путём обхода структуры. Линейный поиск подходит для массивов и связных списков, а поиск в ширину и в глубину — для графов и деревьев. Такие алгоритмы универсальны и не требуют предварительной обработки, но имеют сравнительно высокую временную сложность $O(n)$.
- Поиск по хеш-таблице, поиск в дереве и двоичный поиск позволяют быстро найти элемент в соответствующей структуре данных. Их временная сложность может составлять $O(\log n)$ и даже $O(1)$, однако обычно для них нужны дополнительные структуры данных.
- На практике для выбора подходящего метода учитывают объём данных, требования к скорости поиска и частоту запросов и обновлений.
- Линейный поиск подходит для малых или часто обновляемых наборов данных, двоичный — для больших отсортированных массивов. Поиск по хеш-таблице удобен, когда важна скорость запросов и не нужен поиск по диапазону. Поиск в дереве подходит для больших изменяемых наборов, где нужно сохранять порядок и выполнять запросы по диапазону.
- Замена линейного поиска поиском по хеш-таблице — распространённый способ ускорить алгоритм. Временная сложность поиска при этом может снизиться с $O(n)$ до $O(1)$.
