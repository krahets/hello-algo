# Итоги

### Главное в этой главе

- Двоичное дерево — нелинейная структура данных, воплощающая разделение задачи надвое по принципу «разделяй и властвуй». Каждый узел хранит значение и два указателя: на левого и правого потомков.
- Левый потомок узла двоичного дерева вместе со всеми узлами под ним образует левое поддерево этого узла. Аналогично правый потомок со своими потомками образует правое поддерево.
- К основным понятиям двоичного дерева относятся корень, лист, уровень, степень, ребро, высота и глубина.
- Инициализация двоичного дерева, вставка и удаление узлов выполняются примерно так же, как соответствующие операции в связном списке.
- Основные виды двоичных деревьев — совершенные, полные, строгие и сбалансированные. Совершенное дерево имеет идеальную форму, а вырождение в связный список — худший случай.
- Двоичное дерево можно представить массивом: значения узлов и пустые позиции располагают в порядке обхода по уровням, а роль указателей выполняют формулы, связывающие индексы родителя и потомков.
- Обход двоичного дерева по уровням — это поиск в ширину. Он распространяется наружу волна за волной, уровень за уровнем, и обычно реализуется с помощью очереди.
- Прямой, симметричный и обратный обходы относятся к поиску в глубину. Сначала обход идёт по ветви до конца, затем возвращается и продолжает путь. Обычно его реализуют с помощью рекурсии.
- Двоичное дерево поиска позволяет эффективно искать элементы. Временная сложность поиска, вставки и удаления равна $O(\log n)$. Если дерево вырождается в связный список, временная сложность каждой из этих операций возрастает до $O(n)$.
- АВЛ-дерево — сбалансированное двоичное дерево поиска, которое поддерживает баланс с помощью поворотов даже после многократных вставок и удалений.
- В АВЛ-дереве применяют правый и левый повороты, а также двойные повороты: сначала правый, затем левый или сначала левый, затем правый. После вставки или удаления узла повороты выполняют снизу вверх, чтобы восстановить баланс.

### Q & A

**Вопрос**. Если двоичное дерево состоит из одного узла, равны ли высота дерева и глубина корня $0$?

Да. И высоту, и глубину обычно определяют по числу рёбер на пути.

**Вопрос**. Говорится, что вставка и удаление в двоичном дереве обычно требуют нескольких согласованных действий. Какие именно действия имеются в виду? Речь об освобождении ресурсов дочерних узлов?

Рассмотрим двоичное дерево поиска. При удалении узла различают три случая, и в каждом из них нужно выполнить несколько действий с узлами.

**Вопрос**. Почему для обхода двоичного дерева в глубину есть три порядка — прямой, симметричный и обратный? Для чего они нужны?

Как массив можно обходить в прямом или обратном порядке, так и для двоичного дерева мы можем выбрать прямой, симметричный или обратный обход, чтобы получить результат в нужном порядке. Например, в двоичном дереве поиска выполняется соотношение `значение левого потомка < значение корня < значение правого потомка`. Поэтому обход в порядке «левое поддерево $\rightarrow$ корень $\rightarrow$ правое поддерево» даёт упорядоченную последовательность узлов.

**Вопрос**. Правый поворот меняет связи между несбалансированным узлом `node`, `child` и `grand_child`. А как же прежняя связь родителя `node` с самим `node`? Разве она не разорвётся после поворота?

Посмотрим на это с точки зрения рекурсии. Функция правого поворота `right_rotate(root)` получает корень поддерева, а в конце команда `return child` возвращает корень поддерева после поворота. Связь нового корня поддерева с его родителем устанавливается после возврата из функции. Сам правый поворот за эту связь не отвечает.

**Вопрос**. Чем в реализации на C++ определяется распределение функций между `private` и `public`? Почему функции `height()` и `updateHeight()` находятся соответственно в `public` и `private`?

Это зависит прежде всего от того, где используется метод. Если он нужен только внутри класса, его делают `private`. Например, пользователю незачем вызывать `updateHeight()` отдельно: это лишь один из шагов вставки или удаления. А `height()` возвращает высоту узла, подобно тому как `vector.size()` возвращает размер вектора. Поэтому для удобства метод делают `public`.

**Вопрос**. Как построить двоичное дерево поиска из набора входных данных? Важен ли выбор корня?

Да. Построение дерева показано в методе `build_tree()` в коде двоичного дерева поиска. Чтобы выбрать корень, обычно сначала сортируют входные данные, берут средний элемент в качестве корня и рекурсивно строят левое и правое поддеревья. Так дерево получается максимально сбалансированным.

**Вопрос**. Обязательно ли в Java сравнивать строки методом `equals()`?

Для примитивных типов Java оператор `==` проверяет равенство значений двух переменных. Для ссылочных типов два способа сравнения работают по-разному.

- `==` проверяет, указывают ли переменные на один объект, то есть на одно и то же место в памяти.
- `equals()` проверяет, равны ли значения двух объектов.

Поэтому для сравнения значений следует использовать `equals()`. Однако строки, созданные с помощью `String a = "hi"; String b = "hi";`, хранятся в пуле строковых констант и ссылаются на один объект. В этом случае содержимое двух строк можно сравнить и с помощью `a == b`.

**Вопрос**. Перед обработкой последнего уровня при обходе в ширину в очереди находится $2^h$ узлов?

Да. Например, у совершенного двоичного дерева высоты $h = 2$ общее число узлов $n = 7$. Тогда число узлов последнего уровня равно $4 = 2^h = (n + 1) / 2$.
