14.4   Задача о рюкзаке 0–1¶

Задача о рюкзаке — одна из самых распространённых в динамическом программировании. С неё удобно начинать знакомство с методом. У задачи много разновидностей: рюкзак 0–1, неограниченный рюкзак, рюкзак с ограниченным числом экземпляров каждого предмета и другие.

В этом разделе разберём самый распространённый вариант — рюкзак 0–1.

Question

Даны \(n\) предметов. Предмет с номером \(i\) имеет вес \(wgt[i-1]\) и стоимость \(val[i-1]\). Вместимость рюкзака равна \(cap\). Каждый предмет можно взять только один раз. Какую максимальную стоимость можно набрать, не превысив вместимость?

На рисунке номера предметов \(i\) начинаются с \(1\), а индексы массивов — с \(0\). Поэтому предмету \(i\) соответствуют вес \(wgt[i-1]\) и стоимость \(val[i-1]\).

Иллюстрация 14-17: Рюкзак 0–1: оптимальный набор при вместимости 50

Из пяти предметов выбираем банан весом 20 и виноград весом 30. Они полностью заполняют рюкзак вместимостью 50 и дают максимальную стоимость 270.

В задаче о рюкзаке 0–1 каждый предмет можно взять не более одного раза. Требуется максимизировать суммарную стоимость, не превысив допустимый вес. На рисунке 5 предметов, cap=50. Номерам i от 1 до 5 соответствуют индексы массивов i-1 (на рисунке заголовки wgt[i-1] и val[i-1]).

Слева вверху таблица с номерами от 1 до 5, значками, весами и стоимостями пяти предметов (все данные приведены в таблице). Строка банана под номером 2 выделена светло-оранжевым, строка винограда под номером 3 — светло-фиолетовым. От обеих идут стрелки к фиолетовому рюкзаку справа вверху с подписью «Вместимость рюкзака cap = 50».

Внизу в рамке написано «Максимальная стоимость: 270». Значки банана и винограда поясняют оптимальный набор: положить в рюкзак банан и виноград общим весом 50.

По входным данным банан № 2 и виноград № 3 весят 20+30=50 и стоят 120+150=270. Это максимум среди допустимых сочетаний, больше, например, чем 260 за предметы 1 и 4 или 240 за один предмет 5. Эти вычисления и сравнения дополняют рисунок и основаны на его данных.

В задаче о рюкзаке 0–1 мы делаем выбор \(n\) раз: для каждого предмета решаем, пропустить его или взять. Значит, задачу можно представить деревом решений.

Нужно найти максимальную стоимость предметов при ограниченной вместимости рюкзака. Такая постановка подсказывает, что, вероятно, подойдёт динамическое программирование.

Шаг 1. Описать выбор на каждом шаге и определить состояния для таблицы \(dp\)

Если пропустить предмет, доступная вместимость не изменится, а если взять его — уменьшится. Отсюда определение состояния: номер рассматриваемого предмета \(i\) и вместимость рюкзака \(c\). Обозначим состояние \([i, c]\).

Подзадача для состояния \([i, c]\): найти максимальную стоимость при выборе из первых \(i\) предметов для рюкзака вместимостью \(c\). Обозначим ответ \(dp[i, c]\).

Требуется вычислить \(dp[n, cap]\), поэтому нам понадобится двумерная таблица размера \((n+1) \times (cap+1)\). Обозначим её \(dp\).

Шаг 2. Найти оптимальную подструктуру и вывести формулу перехода

Когда решение по предмету \(i\) принято, остаётся подзадача для первых \(i-1\) предметов. Возможны два случая.

  • Пропустить предмет \(i\). Вместимость не меняется, переходим в состояние \([i-1, c]\).
  • Взять предмет \(i\). Вместимость уменьшается на \(wgt[i-1]\), стоимость возрастает на \(val[i-1]\), а оставшаяся подзадача имеет состояние \([i-1, c-wgt[i-1]]\).

Теперь видна оптимальная подструктура: максимальная стоимость \(dp[i, c]\) равна большей из двух стоимостей — без предмета \(i\) и с предметом \(i\). Отсюда следует формула перехода:

\[ dp[i, c] = \max(dp[i-1, c], dp[i-1, c - wgt[i-1]] + val[i-1]) \]

Если вес текущего предмета \(wgt[i - 1]\) больше оставшейся вместимости \(c\), единственный вариант — пропустить его.

Шаг 3. Определить граничные условия и порядок переходов

Если предметов нет или вместимость равна \(0\), максимальная стоимость равна \(0\). Поэтому первый столбец \(dp[i, 0]\) и первая строка \(dp[0, c]\) заполняются значением \(0\).

Состояние \([i, c]\) зависит от состояния сверху \([i-1, c]\) и состояния выше и левее \([i-1, c-wgt[i-1]]\). Достаточно обойти всю таблицу \(dp\) в прямом порядке двумя вложенными циклами.

Запишем три решения в таком порядке: полный перебор, поиск с мемоизацией, динамическое программирование.

1.   Способ 1. Полный перебор¶

Опишем элементы рекурсивного поиска.

  • Параметры рекурсии: состояние \([i, c]\).
  • Возвращаемое значение: решение подзадачи \(dp[i, c]\).
  • Условие остановки: когда предметов больше нет (\(i = 0\)) или оставшаяся вместимость равна \(0\), завершаем рекурсию и возвращаем стоимость \(0\).
  • Отсечение: если предмет тяжелее, чем позволяет оставшееся место, его можно только пропустить.
knapsack.py
def knapsack_dfs(wgt: list[int], val: list[int], i: int, c: int) -> int:
    """Рюкзак 0–1: полный перебор"""
    # Если предметы закончились или места не осталось, вернуть стоимость 0
    if i == 0 or c == 0:
        return 0
    # Если предмет тяжелее допустимого, остаётся только пропустить его
    if wgt[i - 1] > c:
        return knapsack_dfs(wgt, val, i - 1, c)
    # Вычислить максимальную стоимость без предмета i и с ним
    no = knapsack_dfs(wgt, val, i - 1, c)
    yes = knapsack_dfs(wgt, val, i - 1, c - wgt[i - 1]) + val[i - 1]
    # Вернуть большую из двух стоимостей
    return max(no, yes)

Визуализация выполнения

Во весь экран >

На рисунке от каждого предмета отходят две ветви поиска: пропустить или взять. Поэтому временная сложность составляет \(O(2^n)\).

В дереве рекурсии видны повторяющиеся подзадачи, например \(dp[1, 10]\). Когда много предметов и велика вместимость рюкзака, повторов становится гораздо больше, особенно если многие предметы имеют одинаковый вес.

В отдельном примере с тремя предметами и вместимостью 30 два разных пути выбора ведут в состояние dp[1, 10] и повторно раскрывают его поддерево.

В задаче о рюкзаке 0–1 каждый предмет можно взять не более одного раза. Здесь отдельный пример на 3 предмета, отличный от предыдущего рисунка и основной программы. Вместимость cap = 30, веса равны 10, 20, 20, стоимости — 60, 110, 120 (см. таблицу). Значение dp[i, c] — максимальная стоимость при выборе из первых i предметов с доступной вместимостью c. В заголовках рисунка стоят wgt[i] и val[i] с нумерацией i от 1, а код обращается к массивам по индексу i-1.

Если предмет помещается, сравниваем стоимость без него dp[i-1, c] и с ним dp[i-1, c-wgt[i-1]] + val[i-1] и берём большую. Если он не помещается, остаётся только ветвь пропуска. При отсутствии предметов (i = 0) или нулевой вместимости (c = 0) возвращаем 0.

От корня dp[3, 30] рекурсия рассматривает предмет 3 (ананас, вес 20, стоимость 120), затем предмет 2 (арбуз, вес 20, стоимость 110) и предмет 1 (яблоко, вес 10, стоимость 60). Предметы 2 и 3 весят одинаково, по 20. Пути «пропустить 3, взять 2» (dp[3, 30] → dp[2, 30] → dp[1, 10]) и «взять 3, пропустить 2» (dp[3, 30] → dp[2, 10] → dp[1, 10]) оба расходуют 20 единиц вместимости. Остаётся место на вес 10 и только предмет 1 для выбора, то есть оба пути ведут к одной подзадаче dp[1, 10].

Полный перебор не запоминает решения. Оба вхождения dp[1, 10] раскрываются по отдельности и сравнивают dp[0, 10] без предмета 1 с dp[0, 0] + 60 при его выборе. В результате подзадача dp[1, 10] полностью раскрывается дважды, и второй расчёт повторяет первый.

В правом поддереве dp[2, 10] осталось место на вес 10, а предмет 2 весит 20. Узел dp[1, -10] с подписью «Отсечение: вес предмета > вместимости рюкзака» лишь показывает исключённую ветвь с превышением веса. Код проверяет вес перед рекурсией и при превышении вызывает только ветвь пропуска dp[1, 10]. Вызова с отрицательной вместимостью не происходит.

2.   Способ 2. Поиск с мемоизацией¶

Чтобы решать каждую повторяющуюся подзадачу лишь раз, сохраним результаты в массиве mem. Ячейка mem[i][c] соответствует \(dp[i, c]\).

С мемоизацией время работы определяется числом подзадач и составляет \(O(n \times cap)\). Реализация:

def knapsack_dfs_mem(
    wgt: list[int], val: list[int], mem: list[list[int]], i: int, c: int
) -> int:
    """Рюкзак 0–1: поиск с мемоизацией"""
    # Если предметы закончились или места не осталось, вернуть стоимость 0
    if i == 0 or c == 0:
        return 0
    # Если результат сохранён, сразу вернуть его
    if mem[i][c] != -1:
        return mem[i][c]
    # Если предмет тяжелее допустимого, остаётся только пропустить его
    if wgt[i - 1] > c:

    yes = knapsack_dfs_mem(wgt, val, mem, i - 1, c - wgt[i - 1]) + val[i - 1]
    # Сохранить и вернуть большую из двух стоимостей
    mem[i][c] = max(no, yes)

4.   Экономия памяти¶

Каждое состояние зависит только от предыдущей строки. Можно использовать два массива, меняя их ролями, и сократить пространственную сложность с \(O(n \times cap)\) до \(O(cap)\).

А можно ли обойтись одним массивом? Каждое состояние зависит от ячейки прямо над ним или выше и левее. Когда мы начинаем обход строки \(i\), в единственном массиве ещё лежат состояния строки \(i-1\).

  • При обходе вместимостей по возрастанию значение предыдущей строки \(dp[i-1, c-wgt[i-1]]\), нужное для вычисления \(dp[i, c]\), может быть уже перезаписано. Тогда один и тот же предмет можно ошибочно учесть несколько раз.
  • При обратном обходе нужные значения сохраняются до чтения, и переход выполняется правильно.

На рисунке показано, как в одном массиве сменяются строки \(i = 1\) и \(i = 2\). Проследите, чем отличаются прямой и обратный порядки обхода.

Иллюстрация 14-21: Сокращение таблицы рюкзака до одной строки

Состояния хранятся в одномерном массиве. Обновление по убыванию вместимости позволяет читать старые значения для предыдущего набора предметов и не брать один предмет повторно.

Даны три предмета: 1 — яблоко (вес 1, стоимость 5), 2 — ананас (вес 2, стоимость 11), 3 — арбуз (вес 3, стоимость 15). Вместимость рюкзака равна 4. Каждый предмет можно взять не более одного раза. Нумерация i начинается с 1, в массивах ему соответствуют wgt[i-1] и val[i-1].

Шесть шагов показывают один полный обратный проход внешнего цикла при i=2, для второго предмета — ананаса. До начала прохода одномерный массив dp[0..4] хранит результат [0, 5, 5, 5, 5] для одного яблока (i=1). Арбуз, предмет 3 (i=3), на всём рисунке ещё не обработан. Значение dp[c] — максимальная стоимость при выборе из уже рассмотренных предметов с общим весом не более c. Полностью заполнять рюкзак не требуется.

При обработке ананаса (вес 2, стоимость 11) для c ≥ 2 сравниваем два варианта. Без ананаса сохраняется старое dp[c]. С ананасом берём старое значение для меньшей вместимости и прибавляем стоимость: dp[c-2] + 11. Максимум записываем в dp[c]. При обратном обходе c = 4, 3, 2, 1 ячейка слева dp[c-2] ещё не перезаписана и хранит состояние предыдущего прохода (i=1, только яблоко).

При прямом обходе от меньшей вместимости к большей сначала получили бы dp[2] = 11 для вместимости 2, уже выбрав ананас. Затем для вместимости 4 выражение dp[2] + 11 дало бы 22. Тем самым один ананас был бы учтён дважды, что запрещено в рюкзаке 0–1. При обратном обходе вместимость 4 обрабатывается, пока dp[2] хранит старое значение 5, и верный результат равен 5 + 11 = 16.

Вверху каждого кадра показана двумерная таблица 4×5 для сравнения, внизу — фактически используемая строка dp[0..4]. Синие ячейки хранят старые значения прохода i=1, зелёные — обновлённые значения прохода i=2. В конце прохода вся строка снова становится синей: она послужит предыдущей при работе с арбузом. Значения при перекраске не меняются.

knapsack.py
def knapsack_dp_comp(wgt: list[int], val: list[int], cap: int) -> int:
    """Рюкзак 0–1: динамическое программирование с экономией памяти"""
    n = len(wgt)
    # Инициализировать таблицу dp
    dp = [0] * (cap + 1)
    # Переход между состояниями
    for i in range(1, n + 1):
        # Обход в обратном порядке
        for c in range(cap, 0, -1):
            if wgt[i - 1] > c:
                # Если предмет i тяжелее допустимого, пропустить его
                dp[c] = dp[c]
            else:
                # Взять максимум из двух вариантов: без предмета i и с ним
                dp[c] = max(dp[c], dp[c - wgt[i - 1]] + val[i - 1])
    return dp[cap]
